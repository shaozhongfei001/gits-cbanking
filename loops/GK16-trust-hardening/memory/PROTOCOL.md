# GK16 信任收敛 Loop · 协议

## 目的

> **不推进任何功能。只回答一个问题：我方关于自身产出的每一条结论，是否可信？**
>
> Owner 指令：「分派正反角色，正角色测试、回归、查找问题、修复，
> 反面角色用负例攻击；然后再优化迭代；**直到你再也找不出不可信的问题点才能停下来**。」

## 角色

| 角色 | 职责 | **禁止** |
|---|---|---|
| **正角色 builder/verifier** | 执行检查、回归、发现问题、修复 | 自我宣告"已验证"而不附可复现命令 |
| **反角色 attacker** | **以负例攻击正角色的每一条结论** | 只给观点、不给可复现的攻击制品 |

**同源风险声明**：两个角色由我（同一执行者）扮演。
故**不能**用"正角色说服反角色"作为收敛判据 —— **收敛判据只能是可执行的反例**。

## 每一轮（Round）的强制动作

1. **正角色**：跑全部门禁，记录**原始输出**（不是摘要）
2. **反角色**：对正角色的**每一条结论**，尝试构造一个**能推翻它的可执行负例**
3. **判定**：
   - 构造出反例 → 记 `REFUTED`，正角色修复 → **进入下一轮**
   - 构造不出 → 记 `SURVIVED`，**并必须写出"我尝试了哪些攻击路径"**
4. **收敛**：当且仅当**所有结论均为 SURVIVED 且攻击路径已穷举登记**，方可停止

## 硬约束（本 Loop 的纪律，均由既有失败得出）

| # | 约束 | 来源 |
|---|---|---|
| 1 | **禁止放开只读制品的写权限** | FAIL-51（写坏了受保护制品且 git 无法恢复其权限） |
| 2 | 任何"检查器/门禁"必须有**注入真实缺陷的负例测试** | FAIL-36/40/41 |
| 3 | 负例测试**必须自证注入真的发生了**（否则测试无效） | FAIL-23/49 |
| 4 | 报告数字**必须来自命令输出**，不得凭印象 | 三次计数错误 |
| 5 | 检查器**不得有静默跳过分支**；覆盖缺口必须打印 | FAIL-22/36 |
| 6 | 自检脚本**不得打印它自己扫描的标记文本** | FAIL-47 |
| 7 | 修改后**必须验证还原**（内容 + 权限 + 哈希） | FAIL-51 |
| 8 | **判据文档内容不得改动**（作者已移交独立方） | Owner 裁定 2 |

## 停止条件

> **不是"我觉得没问题了"，而是：**
> ① 所有结论都经过至少一次**可执行的**攻击尝试；
> ② 构造不出反例的项，**已登记攻击路径**；
> ③ 所有仍存在的缺口**已被如实登记**（登记 ≠ 修复，但不得隐藏）。

**"仍有未修复缺口"不妨碍停止 —— 妨碍停止的是"未尝试攻击"或"隐瞒缺口"。**
