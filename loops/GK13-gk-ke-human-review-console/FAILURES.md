# GK13-gk-ke-human-review-console｜Failures（append-only）

## FAIL-2026-09-12-17: 验收问卷是「假表单」（点选后丢失、无法保存/提交）

- **时间**：2026-09-12（人工验收实际操作暴露）
- **Gate**：`gk_ke_console_tests`
- **分类**：**MAJOR**（界面不可用 —— 无法完成其唯一使命：承载人工验收意见）
- **现象**（用户实测）：
  1. 点选选项后**没有任何保存或提交入口**
  2. 在第二部分点选项，**第一部分的已选内容被刷新清空**
- **根因**：
  1. **无状态层**：选项只有 DOM，没有数据模型；`render()` 每次用 `innerHTML = qs(...)`
     整体重写问卷区，DOM 重建 → 用户选择全部丢失。切换页签/点任何按钮都会触发 `render()`。
  2. **无提交通道**：只有"看"，没有"记录"；无保存、无提交、无导出。
- **合规影响**：本控件的**唯一目的**是承载 OC-03/04/05 的人工验收结论。
  表单不可用 = 人工验收无法留痕 = 交付闭环缺失最关键一环。
  这与本程序反复出现的同一类错误一致：**做了形式（有输入框），没做功能（能留存）**。
- **下一动作**：加入持久化状态层 + 保存/提交/导出通道；并把"表单可持久化"写入门禁与变异回归。

### 修复记录（第 1 轮，已闭环）

- **修复**：
  1. **状态层**：`ANSWERS` 对象 + `localStorage` 持久化（刷新不丢）；每道题的 `onchange`
     写入 `ANSWERS` 并自动保存，界面提示"已自动保存（共 N 项）"。
  2. **回填**：`renderConclusion()` 与 `qs()` 均按已存答案回填 `checked`；
     `render()` **末尾强制重绑**结论表 → 彻底修复"切换页签即清空"。
  3. **保存/提交/导出**：
     - 「保存我的填写」→ `localStorage` 持久化
     - 「提交」→ 先校验缺项（列出未填题号），通过后 `POST /api/save` **真实落盘**到
       `evidence/GK-KE-验收答复/答复-<时间戳>.json`，界面回显保存路径
     - 「导出为文件」→ 本地下载 JSON（网络异常时的兜底通道）
     - 「清空重填」→ 二次确认后清空
  4. **服务端**：新增 `POST /api/save`（本控件**唯一**写操作），
     写入路径限定在 `evidence/` 下，**不碰任何权威源**。
- **验证**：
  - `gk-ke-console-tests` 新增 9 项持久化断言（含 `render()` 重绑锚点）+ 服务端端点校验 → **PASS**
  - **变异测试**：删掉 `render()` 末尾的 `renderConclusion()`（完整复现原缺陷）→ 门禁 **FAIL**；
    恢复 → **PASS**
  - 全程序变异回归：`PASS (11/11 mutations caught)`（GK13 已纳入）
  - 端到端：`POST /api/save` 真实落盘，返回 `evidence/GK-KE-验收答复/答复-20260912-164733.json`
