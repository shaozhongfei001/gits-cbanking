**三条硬纪律**
1. **单写者**：TL 文件只有 TL 能写。SubAgent 若需要改门禁/状态，**只提交"登记建议"**（写下 gate id / command / pass_condition / 期望 exit），由 TL 执行 `record_gate.py`。
2. **写域不重叠**：三个 pilot 的写域两两不交（脚本文件名、evidence 前缀、handoff 前缀均不同）。**并行读 + 串行门禁**（脚本自身可并行；`make check`/Maven 类门禁由 TL 串行执行）。
3. **未落盘 = 不存在**：结论必须落文件（带 `文件:行` 或哈希），否则视为未交付。

## 2. loop engineering 波次（每个 PKG 独立跑）

```
PLAN ──▶ ITER(attempt ≤ 8，见 D-14/D-15) ──▶ 自审 ──▶ HANDOFF ──▶ TL 审核 ──▶ 记门禁 ──▶ 板面更新
  │            │                                                    │
  │            └─ 失败：先记 FAILURES.md（TL 侧追加）→ 修 → 重跑原门禁
  └─ 写 memory/waves/<PKG>-PLAN.md（目标/门禁/失败条件）
```

| 阶段 | 产出 | 谁 |
|---|---|---|
| PLAN | `memory/waves/PKG-<X>-PLAN.md`：目标、门禁、失败条件、不做清单 | pilot |
| ITER | 每次 attempt 的**命令 + exit + 输出摘要**追加到 `memory/waves/PKG-<X>-ITER.md` | pilot |
| 自审 | pilot 自检：门禁绿 + 变异复验绿 + 无占位/TODO | pilot |
| HANDOFF | `memory/handoffs/PKG-<X>-HANDOFF.md`：交付物+哈希、门禁实测、**登记建议**、未决与风险 | pilot |
| 审核 | TL 按 §4 审计规格执行；**不采信自述** | TL |
| 记账 | TL 跑 `record_gate.py`（**按真实退出码**；非 0 即 `fail`） | TL |

**max_attempts = 8**（单门禁；2026-09-21 由 `TL-DECISIONS-W-1.md` **D-14** 自 5 调整 —— 权威值以 `LOOP.yaml.repair_policy.max_attempts_per_gate` 为准）；超限 ⇒ pilot 写 `memory/BLOCKED.md` 并停止（TL 复核）。
**D-15（新增，由 QA 第五轮 U-12 触发）**：**不得把"再度调高上限"当常规解法**。若任一门禁再次触顶，出口**只能是**：① 落地 `record_gate.py` 的 `--repair` 与 `--refresh-after-revision` **意图区分**（共享工具改动，需评估对其它 Loop 的影响）；或 ② 走 **ADR 级决定**。**再次单纯上调上限即判 MAJOR**（否则"绑住就抬高"会抵消该控制）。当前消耗（计数/8）：board `7/8`·board_selftest `7/8`·triage(+selftest) `6/8`·refalign `5/8`·refalign_selftest `4/8`·collision `2/8`。

## 3. 无人值守协议

- **自愈阶梯**（自主处理，不停工询问）：① 自愈（修脚本/补夹具/换实现）→ ② 降级（缩小范围但**如实声明未覆盖**）→ ③ 回退（git checkout 自己的改动并改用更保守实现）。
- **只有 5 类硬阻塞**才写 `memory/BLOCKED.md` 并停：缺凭据 / 需求冲突 / 方向性变更 / 自愈耗尽（**现 8 次**，见上 D-14） / 安全隐患。
- **禁止**：为过门禁而弱化断言、删除规则陈述、把 `fail` 改写成 `inconclusive`、把 `NOT_EVALUATED` 包装为通过、`git add .`、动 KERT 仓。
- **红线即刻 STOP**：被要求改 `specs/**`、`generated/**`、`docs/dd/**`、或代签 Owner 文书。

## 4. TL 审计规格（**对每个 PKG 一律执行**）

| # | 审计动作 | 判据 |
|---|---|---|
| AU-1 | 交付物存在性 + 内容哈希 | HANDOFF 声明的每个文件存在；哈希与声明一致 |
| AU-2 | **复跑门禁**（不采信 pilot 日志） | `--gate` 与 `--selftest` 由 TL 亲自跑；exit 与 pilot 声明一致 |
| AU-3 | **回源抽样**（至少 3 条结论） | 随机抽 3 条判定，逐条核对 `文件:行`；有 1 条不成立 ⇒ 退回 |
| AU-4 | **变异有效性**复核 | 至少抽 1 条变异，手工注入 ⇒ 必须 FAIL；恢复 ⇒ PASS |
| AU-5 | 红线扫描 | 本批次写域外的文件是否被改（`git status` 比对）；KERT 是否被写 |
| AU-6 | 记账 | `record_gate.py`；`loop_guard` + `onto1_evidence_board_check` 绿；板面更新 |
| AU-7 | 落盘 | 审计结论写入 `memory/handoffs/TL-AUDIT-W15-<PKG>.md`；不成立则 `FAILURES.md` 先记 |

**审计不通过的处理**：退回 pilot（附具体不成立项）→ 重跑 → 再审计；同一 PKG 退回 ≥2 次 ⇒ TL 接管并记 `BLOCKED.md`。

**交付与证据绑定纪律（2026-09-20 由 D-11 增补，来源：PKG-A3 实证 `FAIL-2026-09-20-W15A3-01`）**

1. **post-DONE 冻结**：报「DONE」后**不得再改**交付物。确需改 ⇒ 作为**新 revision** 重发（新哈希 + 重跑全部日志 + HANDOFF 记版本沿革），不得就地覆盖。
2. **日志自证 revision**：每个 `--gate`/`--selftest` 日志**必须嵌入被测脚本的 sha256**（例：`# artifact=scripts/xxx.py@c5f7b671…`）。没有这一行，日志无法证明它测的是哪一版。
   **TL 修正（2026-09-20T23:45Z）**：原写"置于首行"，但 `loop_guard.py` 有「禁止以 `echo` 起始的假命令」守卫，首行 `echo` 会被判 `dummy command prohibited`。故落地形态为
   `python3 <被测脚本> <模式>; rc=$?; echo "# artifact=<脚本>@$(sha256sum <脚本> | cut -c1-16)"; exit $rc`
   ⇒ **真命令在前（守卫可识别）+ 退出码透传（`rc`/`exit $rc`，防被 echo 的 0 覆盖）+ 哈希行在末尾**。要点不变：日志可自证 revision，且**退出码必须是被测脚本的**。
3. **TL 审计前置**：动审前**连续两次取哈希确认稳定**（间隔数秒）；不稳定 ⇒ 判「在飞」，不出结论、不计缺陷。
4. **不得用手工日志替代脚本输出**：`evidence/*-after-*.log` 必须由命令**直接重定向**产生（可复算），不得人工誊写。
5. **崩溃 ≠ FAIL**：缺输入一律落到**具名 FAIL**（或 exit=3 `INCOMPLETE`），**禁止抛异常**；崩溃会污染记账，且不可复核。

**派工单纪律（2026-09-20 由 D-10 增补，来源：PKG-A2 实证）**：派工单若给出**具体变异设计**，pilot **必须反查该变异是否与门禁语义自洽**。若不自洽（例：要求"单锚点满足即整体通过"，而门禁有多个独立锚点），**应拒绝照做并回报 TL**，而不是为满足字面要求而**摘除/弱化断言**。多锚点门禁的正确变异设计是"**每个锚点各自独立有牙齿**" + "**条件齐备时可转绿（证明非永久红）**"。
