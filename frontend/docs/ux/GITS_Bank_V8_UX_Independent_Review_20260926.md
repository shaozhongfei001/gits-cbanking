# GITS Bank V8 对公经营书桌｜前端 UX 规格独立审阅

**审阅日期**：2026-09-26（北京时间）  
**审阅对象**：INDEX + Part1–Part6，均标注 V8.0 / 2026-09-25；对照 `GITS_Bank_UX_Studio_V8.html` 的视觉定义。  
**审阅角色**：独立 UX/前端规格审阅；**目标**：判断规格是否足以指导复现样稿、支撑完整页面与无障碍验收。  
**证据边界**：收到的是七份设计文档及原 V8 HTML 样稿，没有 CodeBuddy 修改后的代码、运行页面和截图。因此下文的“FAIL”指**规格审阅**，不等于断言当前实现有同样缺陷；实际实现须另做截图、DOM、样式计算与交互验收。菜单、数据和权限的业务权威性也须与现有仓库及批准基线核对。

## 总结论

**规格审阅结果：FAIL，退回修订再做实现对照。** 六个维度都有可定位的实质缺陷。用户指出的侧栏与工作区几乎同色是准确的：`#F9F7F1` 对 `#F4F5F3` 的亮度对比仅约 **1.02:1**。更核心的是：从 HTML 样稿到文字规格，侧栏宽度、顶栏高度、导航选中形态、标题字号和页面叙事均已改变；我此前给出的设计交接未将这些特征明确列为验收项，属于设计交接失职，不能只归因于 CodeBuddy 的执行。

## 为什么实现难以达到 HTML 样稿效果

| 视觉要素 | 原 V8 HTML 样稿 | 当前七份规格 | 可见后果 |
|---|---|---|---|
| 侧边栏 | 220px；暖纸底；左上角小型矿蓝品牌符号 | 256px；顶端 64px 深蓝整块品牌区 | 样稿的轻盈比例与品牌留白被改变；但侧栏底色本身仍与内容区过近。 |
| 顶栏 | 62px | 48px | 页面纵向呼吸感与首屏比例发生变化。 |
| 菜单项 | 40px 高、9px 圆角；选中是 **`#112D40` 深蓝实底 + 白字** | 36px 高、6px 圆角；选中是 **7% 深蓝透明底 + 深蓝字 + 3px 竖线** | 原样稿最强的导航焦点消失；若再叠加近同色侧栏，观感会显得“灰、平”。 |
| 页面标题 | 32px；正文区上方还有眉题、简短引导句 | ObjectHeader 22px；多页仅 `NCard`/`NDataTable` 罗列 | 缺少编辑式信息层级；即使颜色一致也不等于样稿。 |
| 内容表现 | 产品首屏深蓝主题板、克制环形纹样、左右不同权重的内容块 | P4 产品解读主要是选项卡、折叠项、字段路径表；P5 多页仅线框 | 样稿讲的是“先理解再行动”，文档却允许恢复默认组件堆叠。 |

以上是样稿 CSS 与规格文字的直接对照，**尚未看到 CodeBuddy 实际页面**，不能量化实现偏差，也不能断定设计师遵循的是哪一版。样稿自身的侧栏/工作区亮度对比也只有 1.02:1；针对用户要求，需要主动改进样稿设定，而非盲目复刻。

## 对比度复算与判断口径

依据 WCAG 2.1 的相对亮度算法对文档给出的十六进制颜色复算（小数四舍五入）；与 P6:291–301 的“宣称值”比较：

| 组合 | 文档宣称 | 复算 | 判断 |
|---|---:|---:|---|
| `#7B8794` 淡钢色 / `#FFFFFF` 白卡 | 4.6:1 | **3.66:1** | 普通辅助文字不达 AA；11px/13px 并非“大字”。 |
| `#7B8794` / 旧侧栏 `#F9F7F1` | 未列 | **3.42:1** | 组标题若采用此色不达普通文字 AA。 |
| `#7B8794` / 新侧栏候选 `#E4E0D6` | 未列 | **2.78:1** | 改深背景时必须同步调深文字。 |
| `#5A78D8` 按钮悬停背景 / 白字 | 未列 | **4.11:1** | 普通按钮文字不达 AA。 |
| `#3B58C8` 主按钮 / 白字 | 约 5.2:1 | **6.15:1** | 达 AA；文档数字需更正。 |
| `#3A4A5C` 正文 / `#F9F7F1` | 6.8:1 | **8.47:1** | 达 AA；文档数字需更正。 |
| `#112D40` / 白字 | 12.1:1 | **14.25:1** | 达 AA；可用于选中项。 |

正文需至少 4.5:1，大字至少 3:1；承载识别或状态的非文本界面图形通常按相邻颜色 3:1 判断。**WCAG 2.1 AA 的 2.4.7 要求焦点可见，并没有一条“统一必须 2px”的文字阈值**；2px 外轮廓可以作为我们自己的更明确设计要求，但需分别在浅底、深底、滚动容器和高对比模式中验证。官方依据：[WCAG 2.1](https://www.w3.org/TR/WCAG21/)、[对比度解释](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)、[焦点可见解释](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible)。

## 验收与交接

1. **规格修订**：先修正索引项数与路线映射，统一 token、尺寸、侧栏选中态，补齐全页面状态与移动内容替代入口；每项更改引用实际页面/路由/权限，不改 GITS↔DKES 契约。
2. **视觉对照**：在同一数据、字体、缩放比例下输出 1440×900、1024×768、390×844 的样稿基准与实现截图；额外截取侧栏、首屏标题、产品中心、空/载/错/成功、深链详情；并列标出 computed background、width、height、font、radius。不能以“已用同一 token”替代并排视觉评审。
3. **交互检查**：验证深链和刷新后导航选中/面包屑；无权限路由与禁用原因；产品目录移动替代；Tab/Shift+Tab/Esc、抽屉焦点返回与背景隔离；aria-current、标签/描述关系；页面局部错误可重试。
4. **门禁**：UX-01/02/03/04/06/07/08/09/10 的 MAJOR 问题修完且提供运行态证据后，才能把**设计规格**从 FAIL 复审为 PASS 或 PASS_WITH_NOTES。当前报告不构成业务菜单批准、正式验收或生产无障碍合规声明。
