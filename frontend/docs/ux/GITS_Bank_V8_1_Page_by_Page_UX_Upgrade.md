# GITS Bank V8.1｜逐页 UX 优化与视觉提升设计

**版本**：V8.1 设计提案 · 2026-09-26  
**输入**：V8 HTML 样稿、V8 UX Spec 索引及 Part1–Part6、`GITS_Bank_V8_UX_Independent_Review_20260926.md`。  
**覆盖**：索引中的 23 个桌面/登录页面 + Part6 明列的 4 个移动专页，共 **27 个页面**。  
**性质**：可交给 CodeBuddy 设计师实施的视觉与交互改进规格；路由、真实字段、数据、权限以仓库及批准业务基线为准。本文中的页面名称与路径是原规格的索引值，不表示已确认真实实现。保持 GITS↔DKES 现有契约，不以视觉改造改写服务职责。

## 0. 设计判断

先前审阅报告能定位缺陷，却无法让设计师知道**每页应呈现什么视觉层次、什么操作在首屏、哪些状态不能空白**。V8.1 的目标是把“对公经营书桌”做成一个能安静处理复杂工作的专业界面：左侧是有厚度的暖纸导航，工作区是浅灰白纸面；矿蓝构成品牌和重要对象锚点，靛蓝只承担可点击动作，青绿只表达已经确认的状态。深色主题板只出现在少数需要强锚定的页面，避免所有页面都变成同一种仪表盘。

### 0.1 三条不可丢失的视觉特征

1. **明确边界**：侧栏 `#E4E0D6`、工作区 `#F4F5F3`、内容纸面 `#FFFFFF`；不能让侧栏和工作区再次几乎同色。浅底上的辅助文字须同步加深。
2. **强弱分明**：选中导航用 `#112D40` 实底白字、40px 高、9px 圆角；页面主标题桌面约 30–32px，局部区块标题 18px。页面中最多一个最强视觉块，避免每个 NCard 都加边框、阴影和主按钮。
3. **关系先于数据**：每页先回答“我正在处理哪个客户/任务/产品、现在处于什么状态、下一步是什么”，然后才展开指标、表格和技术字段。

## 1. 全局视觉与交互施工规格

### 1.1 Token 与组件底座

| 用途 | 建议值 | 使用边界 |
|---|---|---|
| 品牌锚定 | `#112D40` | 左上品牌标记、导航选中、产品首屏/对象封面；不能给所有按钮涂深蓝。 |
| 主操作 | `#3B58C8`；hover `#2C46AE` | 主要 CTA、可点击文字、选中的页内标签。白字在两态都满足普通文本对比。 |
| 侧边栏 / 工作区 / 面板 | `#E4E0D6` / `#F4F5F3` / `#FFFFFF` | 侧栏要使用新变量 `--v8-sidebar-bg`，与登录页原 `--v8-canvas` 解耦。 |
| 标题 / 正文 / 辅助文字 | `#1A2332` / `#3A4A5C` / `#4B5961` | 不再以 `#7B8794` 承载 11–14px 的重要信息。 |
| 确认 / 待核 / 风险 | `#1A827E` / `#836239` / `#C0392B` | 颜色与文字、图标并用；温砂色 `#C49A6C` 仅作少量装饰，不代替警告。 |
| 纸面分割 / 阴影 | `#D8DEE4`；静态卡片极轻 `0 1px 2px rgba(17,45,64,.05)` | 主要靠版式、留白和 1px 分隔线建立层次；抽屉/浮层才用更深阴影。 |
| 桌面侧栏 / 顶栏 | 220px / 62px | 侧栏中段单独滚动；品牌标记及用户区保持可见。中宽屏可收至 60px；窄屏进入抽屉。 |
| 页面内容 | 最大宽度约 1240px；大屏左右内距 34px；中屏 24px；手机 16px | 页首留 32px 左右上方呼吸空间。页内双栏优先 `minmax(0, 1.7fr) minmax(260px, .85fr)`；不足则自然转单栏。 |
| 字号 | 页标题 30–32px；区块标题 18px；正文 14px；辅助 12–13px | 11px 仅用于非关键眉题/图标编号；不得让整个产品页维持 11px。 |
| 圆角 / 控件高度 | 面板 12–14px；菜单 9px；按钮 8px；桌面菜单 40px，手机触控项约 44px 或以上 | 不改动既有组件行为；对 Naive UI 统一注入主题变量，不逐页零散覆写。 |

**视觉焦点**：浅色菜单用明确的靛蓝外轮廓；深蓝选中菜单用白色内外分层焦点，不能把透明 22% 蓝环当成通用聚焦样式。`prefers-reduced-motion` 缩短非必要运动。所有错误、待核、禁用原因有可读文字，不仅靠颜色。

### 1.2 页面骨架与四态（覆盖下列全部数据页）

每页统一顺序：**位置/面包屑 → 对象或任务标题 + 状态 + 主要操作 → 当前问题/主要工作面 → 依据与详情**。有对象上下文时显示对象名称与可回退路径；对象名称未经授权不得出现在导航或错误信息中。常态首屏最多一个主 CTA，次要动作收在相邻的次级按钮或操作菜单。

| 情况 | 视觉及交互要求 |
|---|---|
| idle / 未选择 | 解释缺少的客户、旅程、产品或筛选条件，给出可操作的选择入口；不显示“系统尚未加载”伪错误。 |
| loading / 首次请求 | 骨架保持页面的标题、工具栏、行/卡/文档形状，已有页面框架不消失；局部刷新仅在局部提示。 |
| success / 有数据 | 当前对象、时间、来源、单位明确；有“下一步”但不得自动跳过人工确认。 |
| success / 真空数据 | 用场景文案解释“确实没有记录”，并在有权限时给出新建或调整筛选入口；不能展示演示假行。 |
| error / 整页或分区失败 | 指明失败范围，保留可保留的旧数据与上下文；提供就地重试/返回；不让报错遮盖整个 Shell。 |
| disabled / 不可操作 | 操作边上常显原因和解除路径；tooltip 仅补充。权限不足与业务前置条件不满足分开表述。 |

四态是最低要求，**成功但空**与**局部刷新/局部错误**须额外覆盖。未在现有接口中出现的数据不得为充版面而虚构；缺真实内容时仍应保持版式结构，以真实空态承接。

### 1.3 菜单、路径与右侧二级导航

沿用“经营 / 客户 / 产品 / 方案 / 分析”五组作为**候选视觉分组**，先按仓库实际路由和权限制作一张单一映射表，再确定每一项的入口。原索引宣称 19 项而正文只列 17 项；`/product-center` 与 `/product-knowledge` 的“产品解读/产品知识”名称相互冲突。不得仅为凑 19 项造菜单。

- **全局侧栏**承载跨客户进入的页面；**客户详情内导航**承载该客户的经营、访前、访后和持续经营路径；**产品阅读内导航**承载族/产品/章节；**推荐步骤条**承载“产品解读 → 客户体检 → 受控推荐”的进程，不把三个不同层级混成重复菜单。
- 若实际业务基线要求体检与推荐在全局菜单可见，按真实路由保留，并通过上下文入口明确“先选客户/先读产品”；差异提交业务归属审阅，视觉实现可以先完成而不改写业务语义。
- `routeMeta` 按真实路径定义组、菜单项、对象详情标题及父链；详情页应显示例如“客户 / 客户组合 / 当前客户”。刷新和深链保持选中；不同角色不展示无权菜单。
- 侧栏有 17 个以上条目时，组标题保持可展开，展开态中段独立滚动，收起态图标必须用一致的图标集及可读名称，不用“◧◈◉”占位符。移动抽屉具有遮罩、Esc、焦点进入/回返、背景不可聚焦、关闭后恢复滚动。

## 2. 逐页优化｜Part1：登录与经营总览（2 页）

### 01 登录页 `/login`

**构图**：保留样稿的居中纸卡：页面用暖纸底和极淡线性纹理，中央卡片宽约 420px；顶部 72px 深矿蓝品牌条承载品牌标记与产品名，下方白色表单区有 26px 标题、简短说明、输入框与 44px 登录按钮。纹理不进入表单，错误提示贴在输入框附近，不放虚假的客户 KPI。卡片的留白、对齐及蓝白界面用一张冻结的登录首屏截图作基准。  
**行为**：真实环境仅展示现有 API Key/认证方式；“内网开发环境”仅在对应环境显示。空输入定位至字段、认证中按钮锁定并说明、失败保留已输入但避免泄露凭证；成功进入有权限的初始页。手机改为单栏，品牌面缩为上方 96px 标题区，表单首屏可见。

### 02 经营总览 P01 `/workbench`

**构图**：沿样稿的“今天的经营重点”：眉题+32px 标题+一句当前工作说明；主列 2/3 放可排序行动队列，右列 1/3 放最近经营脉络与待完成承诺。深蓝只用于一块精选的当前任务提示，不做四个巨型数字宫格。每条行动行有客户、触发原因、时间、风险文本和明确“进入客户”链接；数字排序分不取代可解释原因。  
**行为与状态**：未选客户时“一键访前”旁常显原因和“选择客户”；loading 用 3–5 行骨架，空队列提示“目前没有待处理行动”，失败在队列区重试，右侧独立加载不牵连主列。1024px 右列下移；手机只保留优先事项和一个主操作，其他收折叠段。

## 3. 逐页优化｜Part2：客户与信号（4 页）

### 03 客户组合 P02 `/accounts`

**构图**：搜索与筛选位于标题下统一工具栏；下方默认密度适中的列表，切换卡片后为 3/2/1 列。客户名和下一步行动比行业/ID 更突出；风险采用文字+小色标，筛选结果数和筛选条件始终可见。卡片只在悬停/焦点时轻抬，不使用旧版 `#003366` 标题或高阴影。  
**行为与状态**：表格行通过客户名链接进入详情，不能依赖整行点击；搜索无结果有清除条件，真实组合为空有回到总览入口；加载保持筛选栏与网格骨架，列表失败可就地重试。窄屏由多列表格降为客户摘要卡，保留风险与下一步行动。

### 04 客户记录 P04 `/customers/:id`

**构图**：页首是“客户身份条”：名称、行业/层级/当前经营阶段、资料核验状态；下接客户内页标签。首屏左侧是经营关系、最近信号和下一次行动，右侧窄栏显示已授权的关键指标与更新时间；交易明细下移，不把四张 KPI 卡当页面主角。标题和状态始终来自真实客户对象。  
**行为与状态**：四个子标签保存 URL/页面状态与焦点；深链失效给客户不存在/无权的区别，局部交易失败不抹掉身份条；指标无来源或过期需注明。手机身份条换两行，标签横向可滚动且焦点可见。

### 05 经营信号 P08 `/signals`

**构图**：设计成“待判断信号台”：上方 3 个领域标签和搜索/类型/状态筛选，主列表第一列突出客户与一句业务影响，状态/来源/时间落在同一阅读行；右侧或展开行显示证据与下一步操作。风险红仅用于确实风险，商机类不用红色制造紧张。  
**行为与状态**：筛选空态与真实无信号空态文案分开；详情 `/signals/:id` 在仓库存在时用真实链接，否则标待核对，不写死不存在的路由。加载是列表行骨架；数据失败保留筛选项并就地重试。手机信号按“客户—摘要—行动”纵排。

### 06 经营旅程 P11 `/engagement`

**构图**：页首展示正在服务的客户、旅程目标、最后更新；三阶段路径作为主视觉水平线，当前阶段下方显示“当前必须完成的工作”清单，右侧是客户事实小摘要。阶段点只有完成/当前/待开始三种语义，不以彩色连线暗示已完成未核验的工作。  
**行为与状态**：进入访前是唯一主 CTA；“完成旅程”仅在满足真实前置条件时出现/启用，并显示原因。未选旅程时提供选择入口；步骤或客户事实加载失败分区重试；手机步骤变为纵向时间线。

## 4. 逐页优化｜Part3：访前、会中、访后（5 页）

### 07 访前目标与缺口 P14-1 `/previsit/gaps`

**构图**：左列用三组“待解决的问题”展示 KYC、产品、信息缺口；每组的标题、数量、优先级与负责动作在同一行。右侧始终显示本次拜访目标与成功标准；缺口详情展开显示来源和补齐方式，避免一整页 NDescriptions。步骤轨道保留本次旅程 ID 和客户。  
**行为与状态**：未选择客户/旅程阻止进入并提供回退；空缺口明确“暂无待补齐项”，不等于已具备推荐条件；缺口数据失败不允许按“已补齐”推断。手机三组折叠成纵向问题卡，下一步固定于末尾而非遮挡内容。

### 08 访前证据装配 P14-2 `/previsit/evidence`

**构图**：上方一条简短的“可用于本次拜访 / 待核对 / 缺失”装配摘要；左列是证据源清单，中央是选中证据的摘要与引用，右列在足够宽时显示来源、版本、更新时间。不是“已装配”三个同形卡片后留白。证据缺失区采用边界提示，不用虚构文本填满。  
**行为与状态**：缺失、冲突、过期不能显示为确认态；点击证据须到真实引用源或说明不可用。首屏骨架保留来源清单；单项失败保留其它证据。1024px 以下改为清单+明细两段，版本信息进入显式详情区。

### 09 访前包预览 P14-3 `/previsit/pack`

**构图**：一张“文档纸面”承载访前报告，宽 720–800px，左侧或页内目录定位目标、客户现状、证据缺口、沟通议题；引用号就近显示，右侧独立展示话术与会中议程，不与报告正文混排。LLM 内容标明生成时间、输入范围、待人工确认点。  
**行为与状态**：报告生成中保留章节骨架，失败提供重试与回到证据装配；无话术时不伪造渠道内容；进入会中前仍可查看未解决证据。Markdown 安全渲染并保持标题语义；窄屏目录收起，报告正文单栏可重排。

### 10 会中协作 P15 `/in-meeting/:id`

**构图**：会中以笔记为主工作面，占 2/3 宽度；客户关键信息和建议占右侧 1/3，建议是标有来源和不确定性的辅助卡片，不在笔记旁自动弹跳。页首小型状态条显示客户、议程、记录保存状态，整体低干扰。  
**行为与状态**：笔记输入防止意外丢失，保存中/失败/已保存需真实映射；“采纳/忽略”保留人工动作和可追踪状态。若没有实时建议能力，显示“当前无建议”，不能编造会中推送。结束会议前提醒未保存内容；手机先笔记后建议，允许离线/失败状态可见但不声称已同步。

### 11 访后核验与受控回写 P16 `/postvisit/:id`

**构图**：以“核验清单—回写差异—确认动作”三段组织，中央用并排的原值/拟回写值说明哪些字段会改变，顶部明确对象与目标系统。确认按钮区域与结果状态分隔；失败记录保持在当前页可诊断。  
**行为与状态**：清单不全则禁用确认并常显原因；提交中防重复操作，部分失败不得以整页“成功”覆盖；重试仅针对实际接口支持的失败项。后续行动/承诺回到经营旅程；手机差异逐字段上下对照，确认按钮不遮住差异。

## 5. 逐页优化｜Part4：产品与推荐（4 页）

### 12 承诺事项 P36 `/commitments`

**构图**：页首只突出“近期到期”“逾期需处理”两个可行动摘要；主区按承诺和任务分别列表，右侧放可折叠商机阶段摘要。到期日、客户、负责人、下一动作在同一行，列表的展开态才展示详细描述。避免四 KPI 卡 + 两大表 + 管线平铺。  
**行为与状态**：新建/完成受真实权限和状态控制；逾期用文本+标记，不只红字。无承诺与筛选无结果分开；任务接口失败不遮蔽承诺；手机按到期时间分组的列表代替宽表。

### 13 产品解读 P38 `/product-knowledge`

**构图**：沿样稿的深蓝“产品首屏”作为**本页唯一深色大块**：产品名、族、版本、知识有效性和一句面向客户经理的白话介绍。首屏下用“这是什么 / 适合谁 / 核心条款 / 价格与限制 / 风险与依据”章节展示；底层 `identity.code` 等字段路径收在“查看原始知识字段”折叠区。产品族选择与产品选择合并为清楚的两级控件，减少三排相同的 NTabs。  
**行为与状态**：CONFLICT/STALE 明确“不能据此形成确认性说法”，来源可追溯；产品未选择、无已发布解读、单章节失败、检索失败分别处理。没有客户上下文仍可读产品，不显示适配结论；手机深蓝首屏高度收紧，章节目录成抽屉。

### 14 产品中心 PC1 `/product-center`

**构图**：大屏三栏：左产品目录 220–240px、中阅读区至少约 520px、右依据与版本 240–280px。上方沿样稿保留克制深蓝环境/产品锚点；中栏有清晰的章节目录与可跳转八章（“八章”是否实际存在以仓库为准），右栏注明来源材料、知识状态、更新时间。目录不能与全局侧栏使用同一种选中高亮。  
**行为与状态**：宽度不足时先变两栏，再改“选择产品”抽屉 + 单栏阅读 + 显式“依据与版本”入口；不能简单隐藏目录/治理。章节 sticky offset 取顶栏实际高度，不写死 49px；产品切换记住/重置阅读位置的规则明确。无来源、过期、章节请求失败逐区说明；移动端可搜索产品目录。

### 15 客户体检 / 受控推荐 WP5-1 `/recommendation/:runId`

**构图**：表单创建态只保留“客户→需求/上下文→发起体检”三个有标签的区域；已有 run 显示 **客户事实快照 → 硬条件与缺口 → 候选对比 → 人工决定**，四段不得折叠为一个“推荐分数”。候选卡突出适配依据、限制条件、待核事实及可追溯证据；色彩从浅到重随决策风险增加。  
**行为与状态**：无客户、缺必要输入、上下文装配中、硬条件未通过、知识冲突、待人工决定、人工修改/拒绝/暂缓分别写清动作与提示。只有真正通过前置条件才显示可执行的受控推荐；审批/人工决定不因 UI 美化变为自动。`new` 与 `:runId` 的路由语义从仓库确认；手机候选采用可逐项比较的纵向布局，关键差异不藏入滑动轮播。

## 6. 逐页优化｜Part5：方案、分析与治理（8 页）

### 16 建议书列表 P23 `/proposals`

**构图**：标题下先解释当前“建议书工作区”的真实保存范围；主列表以客户、建议书名、状态、最后编辑为阅读主线，章数/技能/引用做次级信息。新建主操作在右上，导入不可用时原因常显，不要放一个永远灰掉但没有解释的按钮。  
**行为与状态**：原规格 C2 为浏览器会话暂存且不落库，须在列表和详情持续提示“仅本会话可见”，不能画成持久文档库。新会话真实空态不编造记录；新建/返回后的列表位置可恢复；手机改为两行摘要列表。

### 17 建议书详情 P25 `/proposals/:id`

**构图**：采用正式文稿阅读面：左侧章目录（宽屏）、中央纸面章节、右侧或段落旁的引用与待确认项。首页展示客户、目标、生成时间、当前状态；章节内容保留足够行宽与行距，引用置于相关论断附近而非整页尾部。风险/免责声明以清晰边界框出现，不做大面积危险色。  
**行为与状态**：章节加载失败可单章重试；来源不可用/待确认不能与已确认混同；返回保留列表筛选。若 C2 只有会话草稿，深链失效时解释原因并回到列表，不能显示假详情。手机目录折叠，正文单栏。

### 18 经营指标分析 `/analytics/operating-metrics`

**构图**：上方紧凑筛选条与数据时点，左侧分析章节导航仅在宽度足够时存在；主图表下方必须有一行“当前图表说明与口径”，清楚标出单位、周期、样本范围。不能让 196px 侧导航重复挤压全局侧栏。旧版 `#1976d2` 及硬编码 `#2d3748` 全部映射回 V8。  
**行为与状态**：筛选无组合、加载、图表无数据、图表错误分别有占位与重试；图形不能仅凭色彩解释系列，关键数值有表格/文本替代。1024px 起分析导航转页内标签，手机图表纵向排列。

### 19 客户分群分析 `/analytics/segments`

**构图**：左上展示分群问题和维度/阈值控件，中央散点/气泡图与下方客户清单联动；清单显示归类理由。图表旁给“当前选择了什么/覆盖多少客户”的摘要，不凭气泡面积暗示未经证实的价值。  
**行为与状态**：筛选重算时保留旧图并标“更新中”，无匹配客户给清除条件；图表获取失败有文本结果/重试。手机默认先条件与客户列表，图形切换查看；键盘可操作图表点时提供等价列表入口。

### 20 组合看板 `/portfolio`

**构图**：按真实工作状态的 3–4 列并排，各列标题放数量和下一步含义；卡片仅显示客户/任务、到期、风险文字与负责人。使用柔和列背景，避免所有看板列都是有厚边框的白卡。  
**行为与状态**：若现有系统无状态变更接口，本页只读，不因看板样式加入拖拽或假保存；若支持拖动，必须有键盘等效“移动到”操作和结果通知。空列说明“本状态无事项”；移动端转纵向分组而非横向拖动板。

### 21 审批中心 `/approvals`

**构图**：上方待我处理/已处理两个视图；左边列表突出申请人、客户、请求动作、等待时间，详情抽屉/右栏显示依据、变化影响与历史。批准/退回/拒绝的视觉层级由决策风险决定，不用三颗并排同权重的彩色按钮。  
**行为与状态**：按钮只对实际权限、实际审批状态可用，提交需理由/二次核验的地方遵从已有合同；处理中防重，失败保留表单和待办。手机先列表后独立详情页/抽屉，确认动作始终附明确对象名。

### 22 审计追踪 `/audit-trace`

**构图**：以时间轴式审计清单为主，筛选在顶部；每行展示时间、操作、操作者、对象、结果，展开才显示变更前后和证据 ID。白纸基底强调可读性，状态色不掩盖日志原文。  
**行为与状态**：日期筛选无结果与查询失败分离；涉及客户信息按原系统权限遮蔽；下载/导出只在真实权限和功能存在时呈现。窄屏每项按字段标签纵排，时间与状态留在第一行。

### 23 CRM 回写监控 `/crm-writeback`

**构图**：页首用细状态带汇总待回写/进行中/完成/失败；主体先显示失败或需要人工关注的记录，再按时间展开全量。点开记录查看目标对象、字段差异、尝试次数与错误原因。不要用四张巨大彩色数字卡盖住实际待处理记录。  
**行为与状态**：重试按钮仅对仓库既有重试能力开放，明确重试范围/状态；部分成功与失败项分开，不把“进行中”当“成功”。列表加载骨架、无失败记录的正向空态、接口错误的重试路径独立。手机先失败记录，再折叠查看汇总。

## 7. 逐页优化｜Part6：移动专页（4 页）

### 24 移动端今日 `/m/today`

**构图**：首屏只有“今天需要我做的事”、最紧急 1–3 项、一次明确的下一步；底部快捷操作至多三项，名称是动作而非模块。事项摘要卡保持 44px 以上可点区域且不依赖侧栏才能完成核心工作。  
**行为与状态**：无待办时提示可回到客户组合；加载/失败使用与列表相符的单列骨架/就地重试。打开抽屉不遮住背景焦点。

### 25 移动端访前 `/m/previsit`

**构图**：纵向三段“目标—缺口—证据”，每段显示完成程度与仍缺内容；顶部固定客户名和本次拜访时间（有真实数据才显示），底部仅当前阶段的下一步。  
**行为与状态**：缺证据时给回到对应段落的入口，不用整页警告；局部失败保留其它段内容。与桌面 P14 系列使用同一业务状态源，不新增独立结论。

### 26 移动端笔记 `/m/notes`

**构图**：大块可编辑会谈笔记优先，建议内容从下方可展开区域进入；页顶明确“保存中/已保存/失败”，避免用户误判是否同步。  
**行为与状态**：切应用、返回、连接中断时保持草稿并说明实际保存位置；没有真实离线能力不声称“离线已保存”。收起键盘后操作可达，屏幕阅读器能读出保存状态。

### 27 移动端访后 `/m/checkout`

**构图**：用户可见标题用“访后核验”，保留真实路由 `/m/checkout` 直到工程路由评估通过。上方核验项、中间拟回写差异、底部确认区依次排列；重要字段与风险提示不可隐藏在横向滚动。  
**行为与状态**：未核验不得提交；提交中防重复、回写失败显示失败字段和受控重试入口；成功才显示“已完成”。确认按钮的文字包含动作对象，避免“确定”含义不明。

## 8. 补齐原文档提到、但索引未收录的页面/路由

原 Part2 提及 `/signals/:id` 与 `/engagements`，Part1 菜单列 `/needs`、`/recommendation/new`、`/recommendation`，索引未完整覆盖。先查项目路由及权限：**真实存在**则把它们加入页面矩阵并沿上述相邻页面模板补齐专属视图；**不存在**则从可见菜单/导航删除或更正路径。不得悄悄将 27 页宣称为全系统 44 页的完整覆盖，也不得把这些未核路由做成假页面。产品族数量需对照批准产品基线，原 Part4 中只有六族的呈现不能自行断言为全量。

## 9. 逐页验收表的填写方式

每一页交付时填写同一张记录：`页面/真实路由/真实权限`、`样稿基准/改后截图`、`首屏关键对象/唯一主操作`、`idle/loading/success-empty/success-data/error/disabled`、`1440×900/1024×768/390×844/320 CSS px 重排`、`键盘与屏幕阅读器结论`、`数据来源与已知缺口`。27 页逐行留证据，不允许只出一张首页截图。对 WCAG 2.1 AA 的对比度、焦点与重排要求分别按实际渲染检查；表格等二维信息可采用合适的局部滚动，但不可把整页变成横向滚动。官方参考：[WCAG 2.1](https://www.w3.org/TR/WCAG21/)、[Disclosure Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)、[Dialog Modal](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

### 实施优先级

1. **先锁定视觉主线**：侧栏三层底色、深蓝实底选中、220/62/40/32 的关键尺寸、品牌/交互蓝拆分、辅助文字与按钮对比。
2. **再做可复用体验模式**：对象页首、行动列表、旅程步骤、文稿纸面、产品阅读、图表与治理、四态与抽屉。
3. **最后逐页承接业务**：27 页在实际路由权限和数据上落地；未知能力保持真实空态和待核查标签，不伪造实现。

**验收边界**：本文是设计提案；没有 CodeBuddy 当前代码与截图，不对“当前已经整改到何处”作事实判断。菜单改名、业务路径/权限或服务调用的实质变化需用真实仓库和项目既定审批链核对。
