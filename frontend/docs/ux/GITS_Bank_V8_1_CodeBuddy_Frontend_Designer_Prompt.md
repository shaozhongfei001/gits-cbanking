# 给 CodeBuddy 前端设计师的执行提示词｜GITS Bank V8.1 逐页提升

你负责把 GITS Bank 对公经营书桌的 V8 前端进一步做到原 HTML 样稿应有的精致程度，并完成逐页改造。不要只交审阅意见、颜色替换或首页截图；请在现有 Vue 3 / Naive UI / Tailwind 项目中完成可运行的前端设计与验收证据。

## 必读输入与优先级

1. 以仓库当前真实路由、组件、角色权限、已批准业务与产品基线为功能事实来源；服务契约和 GITS↔DKES 边界不因设计任务变化。
2. 用 `GITS_Bank_UX_Studio_V8.html` 作为**视觉参照**，重点观察比例、留白、矿蓝实底选中态、产品页的深色焦点面及内容层次。它只有少量演示屏和虚拟内容，不能当成全量业务页面。
3. 用 `GITS_Bank_V8_1_Page_by_Page_UX_Upgrade.md` 作为**27 页视觉与交互施工规格**；用 `GITS_Bank_V8_UX_Independent_Review_20260926.md` 关闭已定位的 12 项问题；将 `V8-UX-Spec-INDEX.md` 与 Part1–Part6 用作原页面范围和待核对素材。如果旧规格与 V8.1 的视觉数值冲突，以 V8.1 作为待实施设计；业务字段、权限、流程仍以批准基线和实际代码为准。

## 先核对，然后直接改造

先给出一张实际页面清单：页面 ID、仓库路由、菜单/对象上下文入口、权限、现有状态和对应的 V8.1 页码。重点查清旧索引声称“19 项”但正文只有 17 项，以及 `/product-center`、`/product-knowledge`、`/recommendation`、`/recommendation/new`、`/needs`、`/signals/:id`、`/engagements` 的真实归属。真实存在却漏在索引的页面补入施工表；不存在的路由不要为了凑数创建或显示。遇到业务菜单含义未决，保留原有可用路径，在交付表注明待决，不停止其余页面的视觉整改。

第一批先把 Shell 做准：侧栏底色改为 `#E4E0D6`，与工作区 `#F4F5F3`、白色内容纸面形成明确三层；登录页底色与侧栏变量解耦。恢复桌面侧栏约 220px、顶栏约 62px、菜单约 40px、选中菜单 `#112D40` 实底白字、圆角约 9px、主要页面标题约 30–32px。组名及辅助字使用经过实测可读的深色，例如 `#4B5961`；操作蓝 `#3B58C8`，主按钮悬停 `#2C46AE`。统一焦点、间距、边框和 Naive UI 主题；侧栏条目多时中段独立滚动，品牌和用户区域不被挤走。不要把 7 项样稿菜单写死进正式 17 项以上菜单，也不要把“温砂装饰色”当警告色。

第二批按 V8.1 逐页完成：登录、经营总览、客户组合、客户记录、经营信号、经营旅程；三页访前、会中、访后；承诺事项、产品解读、产品中心、客户体检/受控推荐；建议书列表与详情、经营指标、客户分群、组合看板、审批中心、审计追踪、CRM 回写；以及移动今日、移动访前、移动笔记、移动访后，共 **27 页**。每页按文档的“构图 + 行为与状态”落实首屏重点、对象身份、唯一主操作、证据/版本、真实空态和局部错误。统一骨架与组件，但不要把所有页面退化为同一套四个 NCard 和一张表；工作台、旅程、产品阅读、文稿、分析、审计应有各自版式。

页面保留真实数据与权限。不要编造客户、交易、费率、产品适配结论、审批结果或服务成功状态；不得为了凑视觉效果硬编码演示数据到正式页面。客户经理主线仍是持续经营与赢单；“产品解读 → 客户体检 → 受控推荐”必须可理解，后两步的人工判断、来源约束和业务前置条件不能被 UI 自动越过。P23/P25 原 C2 会话暂存与不落库的边界必须诚实呈现。

第三批逐页验收。对每一真实数据页分别核对未选择/idle、首屏 loading、成功有数据、成功但真实空、整页/局部 error、disabled 原因和解锁路径；登录按认证状态验收。产品中心在 1024px 不许保留中栏仅约 280px 的伪三栏，目录和依据在手机上必须能重新进入。移动抽屉需 Esc、遮罩、关闭后焦点返回、背景不可聚焦及滚动恢复；主导航要支持深链刷新后的选中与对象面包屑。用实际渲染核验文字对比、键盘焦点和 320 CSS px 重排，而非仅引用规格里的错误对比度数字。

## 交付回执格式

1. **页面映射表**：27 项逐行标明 `DONE / PARTIAL / ROUTE_NOT_FOUND / BLOCKED_BY_REAL_DEPENDENCY`，列出真实路由、菜单入口、权限、改动文件及偏差原因；额外页面单独列出。不能把不存在的页面记为 DONE。
2. **视觉对照**：同一字体、缩放和真实/合规测试数据下，提交 1440×900、1024×768、390×844 的样稿目标/改后截图。至少提供 Shell、登录、经营总览、客户记录、访前、产品解读、产品中心、推荐、建议书、分析、审批/回写、移动抽屉的并排对比；其它页面按逐页表附可查看截图。标注 computed 侧栏/工作区底色、侧栏/顶栏宽高、导航选中态和页标题字号。
3. **状态证据**：每页提供至少真实空态/加载/错误或受控模拟故障中的适用证据及重试结果，关键业务动作记录禁用原因和解除路径。
4. **代码与 QA**：可复用组件、主题令牌、菜单路由映射、实际修改列表；键盘路径、焦点与对比度检查结果；现有构建和必要测试结果。对未闭合项说明原因、责任方和下一步，不要把“设计图完成”说成“全页已实施”。

请直接完成上述设计和前端改造，先修最影响观感的 Shell，再推进全部页面；每完成一组就与原 HTML 样稿并排看首屏层级。如果某个旧规格的尺寸或颜色会让页面变得更平、更挤，请采用 V8.1 的修订并在回执中记录。
