## 2. 根因一句话

## 4. CVE 适用性核实（决定修复路线）

- **CVE-2026-41707**：Spring Security `DPoPProofJwtDecoderFactory` 重放漏洞（Authentication Bypass by Capture-replay，published 2026-08-25）。
- **受影响范围**：6.5.0–6.5.11；7.0.0–7.0.6；7.1.0。
- **上游修复**：7.0.7 / 7.1.1 / 7.0.6.1 / 7.1.0.1；**6.5.12（Enterprise Support Only）**。
- **本仓适用性**：该漏洞仅影响启用 **OAuth2 DPoP 证明校验**的应用。本仓认证为自定义 `X-API-KEY`（规则 §9），全仓无 DPoP/OAuth2 使用 → 受影响代码路径**不可达 → N/A**。

## 5. 需要 TL 裁决

### 决策 1（主修复，推荐，最小爆炸半径）
在 `dependency-check-suppressions.xml` 新增**精确抑制**：
- 绑定 `CVE-2026-41707` → 仅 `spring-security-core` / `spring-security-web`
- `CLASSIFICATION=NOT_APPLICABLE`，注释写明：本仓自定义 `X-API-KEY` 认证、未用 DPoP，CVE-2026-41707 不可达
- 保留 `AUTHORITY` / `SUPPRESSION_SCOPE` 注释，过 `scripts/dependency-check-guard.py`
- **是否批准？**

### 决策 2（根治路线，备选）
6.5.x 修复版 **6.5.12 仅 Enterprise Support**；开源修复 7.0.7 / 7.1.1 需 **Spring Boot 4.x** 大版本升级。是否纳入 `GKC-boot4-migration` 统一规划，而非为单 CVE 贸然升大版本？

## 6. 附带潜伏项（非本次原因，建议排期）

- **③ 外部依赖 IT 被静默漏跑**：`-Dtest="**/*IT"` 漏掉全部 `*IntegrationTest`（含 Oracle/CRM/LLM 3 个真实外部依赖用例）。当前不会让 CI 失败（好事），但一旦改模式就会崩。建议显式条件化（`@EnabledIfEnvironmentVariable` / Testcontainers / `@DisabledIfSystemProperty`）。→ 属"条件化外部依赖"范畴，与决策 1 的"修安全门禁"是两码事。
- **④ NVD API Key 必需性**（治理文档 `docs/governance/OWNER_AUTH_REQUEST-2026-09-14-NVD-API-KEY.md`）：针对**冷缓存** bootstrap（1h24m–1h54m）。本次缓存热未踩中，但冷缓存仍会触发。建议补齐 `NVD_API_KEY` secret。→ 属 A 类潜伏基建风险，与本次失败区分。
