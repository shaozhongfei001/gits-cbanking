## 1. OC-03｜候选内容与发布 —— 审阅材料

### 1.1 审核规则（C03 §4 双维）

| 维度 | 主要问题 | 责任方 | 本包状态 |
|---|---|---|---|
| **内容认定** | 原文是否支持？主体/时间/数值对吗？来源是否可用于该结论？冲突如何处理？ | 领域知识 Owner / 专家 | ☐ 请确认责任方 |
| **地图与执行认定** | 任务是否需要这项知识？资产是否齐备？Skill 真实存在且合同兼容？权限和调用边界是否正确？ | 岗位流程 Owner + 能力维护者 | ☐ 请确认责任方 |

> 两维**皆通过**才形成可执行用途的地图。
> 研究用途可发布"可检索来源目录 + 未决问题"视图，但 `purposeFlags=RESEARCH` **不能静默升级**成 `RECOMMENDATION`。

### 1.2 发布判定谓词（C03 §5，已逐项落为可执行检查）

```
Publishable(v,p) = ValidSchema(v) ∧ RefClosure(v) ∧ SourceUsable(v,p)
                 ∧ IdentityResolved(v) ∧ NoBlockingConflict(v,p) ∧ ApprovedHash(v,p)
                 ∧ RequiredCapabilitiesReady(v,p) ∧ QualityGate(v,p)
```

**本包实测**：八项**全部为 True** 才发布；任一项为 False 时发布被拒。

### 1.3 状态机

| 层次 | 取值 | 说明 |
|---|---|---|
| 内容版本 | `CANDIDATE` → `IN_REVIEW` → `APPROVED` / `REJECTED` | **APPROVED 后任何内容修改都创建新 CANDIDATE，原审批不继承** |
| 发布过程 | `STAGED` → `PUBLISHED` | |
| 运行有效性 | `ACTIVE` / `STALE` / `REVOKED` / `SUPERSEDED` | **独立登记状态，不改发布内容** |

### 1.4 已建模并**可被触发拒绝**的七类违规（关键：这些是"否定式"防线）

| # | 违规 | 期望行为 | 我实测的结果 |
|---|---|---|---|
| 1 | **审批后改字**（hash 变化） | 阻断发布 | ✅ `CONTENT_CHANGED_AFTER_APPROVAL` |
| 2 | **自审自批**（审核人=提交人） | 拒绝 | ✅ `SELF_APPROVAL` |
| 3 | **过期审批**被计入 | 拒绝 | ✅ `EXPIRED_APPROVAL_COUNTED` |
| 4 | **半发布**（投影未 ready 却 published） | 阻断 | ✅ `HALF_PUBLISH` |
| 5 | **撤销后仍可检索** | 立即不可见 | ✅ `REVOKED_STILL_SEARCHABLE` |
| 6 | **回滚指向已撤销版本** | 拒绝 | ✅ `ROLLBACK_TO_REVOKED` |
| 7 | **用途静默升级**（RESEARCH→RECOMMENDATION） | 拒绝 | ✅ `PURPOSE_FLAG_SILENT_UPGRADE` |

> 以上 7 项经**变异测试**验证：故意破坏判定逻辑后门禁**必须失败**，恢复后通过
> （见 `scripts/gk_ke_mutation_regression.py`，10/10 变异被捕获）。
> **含义**：这些防线不是"文档上写了"，而是"真的会拦"。

### 2.3 确定性计划 `SIM-PLAN-001`

| 步骤 | 执行者 | 依赖 | 副作用 | 说明 |
|---|---|---|---|---|
| `S1` | `SIM-CAP-INTERPRET` | — | `NONE` | 产品解读 |

- **同输入 → 同 `planHash`**（随机 `planId`/`traceId`/创建时间**不改变** hash）

## 3. OC-05｜完整经营闭环（OB-C3）—— 审阅材料

### 3.1 五步闭环（实际数据样本）

| 步 | 环节 | 本包样本数据 |
|---|---|---|
| 1 | **解读** | 基于 `EvidenceBundle`；「客户表示下季度可能需 3000 万」→ 标注为 **`CUSTOMER_STATEMENT`**（客户声明），来源 `SIM-VISIT-003#L14` |
| 2 | **体检** | `purposeKnown=false` → 输出 **`UNKNOWN`** + 补充问题：①本次融资的具体用途是什么？②是否有担保安排？ |
| 3 | **推荐** | `SIM-REC-001`，`isCandidateProposal=true`，**`producesCreditDecision=false`**；建议"访前核实融资用途与担保安排" |
| 4 | **确认** | `confirmationRef=SIM-CONFIRM-001`，确认人 `SIM-RM-001`，绑定 `targetVersion=1` |
| 5 | **模拟跟进** | `CREATE_FOLLOWUP_TASK`，`status=EXECUTED`，回执 `SIM-RECEIPT-001` |

### 3.2 **最关键的业务边界**（请重点审阅）

| # | 边界 | 本包行为 | 为什么重要 |
|---|---|---|---|
| 1 | 「下季度可能需 **3000 万**」 | 标记为 **客户声明**；**不**视为真实贷款需求、**不**视为已批准额度、**不**视为可提款金额 | 防止把客户口头意愿做成授信结论 |
| 2 | 名义未用额度 **800 万** | **不等于**可提款金额 | 防止把"名义额度"当"可用资金" |
| 3 | **用途未知** | 输出 `UNKNOWN` + 补充问题；**不得**因行业图存在「资金需求」关系而通过准入 | 防止用弱关联绕过准入 |
| 4 | 动作白名单 | **仅** `CREATE_FOLLOWUP_TASK` / `RECORD_CONTACT_OUTCOME` | 转账/放款/授信审批**一律拒绝** |
| 5 | **超时** | → `RESULT_UNKNOWN`，**先查目标回执**再判定，**不**直接判失败 | 防止把网络超时误判为业务失败 |
| 6 | **失效版本** | 拒绝（`STALE_TARGET_VERSION_REJECTED`） | 防止对过期目标执行动作 |

### 3.3 已建模并**可被触发拒绝**的六类违规

| # | 违规 | 实测 |
|---|---|---|
| 1 | **白名单外动作**（转账/放款/授信审批） | ✅ `FORBIDDEN_ACTION_REJECTED` |
| 2 | **失效目标版本**被接受 | ✅ `STALE_TARGET_VERSION_REJECTED` |
| 3 | **缺确认引用** | ✅ `MISSING_CONFIRMATION_REJECTED` |
| 4 | **超时直接判失败**（未查回执） | ✅ `TIMEOUT_RESULT_UNKNOWN` |
| 5 | **客户声明当事实** | ✅ `STATEMENT_AS_FACT_REJECTED` |
| 6 | **用途未知却通过准入** | ✅ `UNKNOWN_PURPOSE_NOT_ADMITTED` |
