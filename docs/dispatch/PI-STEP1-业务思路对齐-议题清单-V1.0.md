# 台阶 1 · 业务思路对齐｜议题清单 V1.0

```text
对象：一线客户经理（业务代表）
列席：Tech Lead（仅记录与追问，不输出业务结论）
产出：一页《业务目标与验收口径》，由业务代表签字后生效
时长：建议 60–90 分钟
状态：待组织（未开始，本清单为唯一议题来源）
```

## 0. 会议规则（TL 自我约束）

1. TL 只做两类动作：**记录**、**追问**；**不**回答业务类问题、**不**给业务结论、**不**替业务排优先级。
2. 业务代表未明确的项，一律记 `OPEN`，**不推测、不代填**。
3. 任何结论必须由业务代表口头确认后当场记录，会后签字。
4. TL 可在会后就技术可行性提出**限制条件**（例如"演示数据必须先声明"），但不得据此改变业务目标。

## 1. 议题清单（17 问，每问标注"回答将决定什么"）

### A 组：现状与痛点（4 问）

| # | 问题 | 回答将决定 |
|---|---|---|
| A1 | 你现在要给客户讲一个产品（以法人账户透支为例），从接到问题到能开口，实际做哪几步？每步大概多久？ | 页面是否需要"访前准备"模式；首要效率指标 |
| A2 | 这些信息你从哪拿（产品卡 / 制度汇编 / 群消息 / 问产品经理 / 凭经验）？哪些根本拿不到？ | 数据来源优先级；缺口清单是否算核心功能 |
| A3 | 最近一次"讲错、说不准、被客户问倒"是什么情形？ | 失败模式是"承诺错"还是"找不到"——决定 PC2 主线成立与否 |
| A4 | 合规或审批抽查有没有问过你"这个说法凭什么"？你当时怎么答的？ | 是否需要"证据可追溯"作为 P0；审计场景是否真实存在 |

### B 组：使用者与场景（3 问）

| # | 问题 | 回答将决定 |
|---|---|---|
| B1 | 这个能力的使用者只有你，还是也包括产品经理、合规、新员工？请排序。 | 页面主视角与默认信息密度 |
| B2 | 使用时机：访前准备 / 客户当场提问 / 事后补材料 / 审批答辩 / 新人学习——请多选并排序。 | 是否需要移动端、离线、打印/导出 |
| B3 | 你会在什么场合用（电脑安静环境 / 手机平板 / 客户现场）？ | 布局密度、加载时长容忍度 |

### C 组：价值单位与现状页评价（3 问）

| # | 问题 | 回答将决定 |
|---|---|---|
| C1 | 如果这个页面只能做好一件事，你希望先解决什么？ | **本议题最重要一问**，直接决定 PC2 主线或"不做" |
| C2 | 现有「产品解读与知识」页你用不用？用哪一部分？不用哪一部分？为什么？ | P38 是保留、增强还是被替代 |
| C3 | 什么情况下你会放弃这个页面、回去翻原文？ | **失败判据取样**（用于定义"做成了"的反面） |

### D 组：红线与呈现方式（3 问）

| # | 问题 | 回答将决定 |
|---|---|---|
| D1 | 哪些内容绝对不能出现在页面上、或绝对不能对客户说？（额度 / 利率 / 时效 / 担保方式 / 审批结果……请具体列） | 永久不可承诺清单的条目 |
| D2 | 页面显示"待核验"这种状态你能接受吗？还是宁可它不显示？ | 缺口呈现方式（如实显示 vs 隐藏） |
| D3 | 演示（DEMO）数据出现在页面上，你能接受到什么程度？ | DEMO 标识强度与生产阻断强度 |

### E 组：验收与失败判据（4 问）

| # | 问题 | 回答将决定 |
|---|---|---|
| E1 | 什么样的结果算"这个模块做成了"？请给 1–3 条**可测**现象（例：回答材料清单问题不再需要打开原文）。 | P0 验收口径 |
| E2 | 什么样的结果算失败、应该被撤掉？ | 停止条件 |
| E3 | 需要谁签字才算可以上线？ | 上线门禁链 |
| E4 | 你愿意用多长时间、多大范围做一次小验证（例如只用法人账户透支一个产品试两周）？ | 是否先做单产品试点而非全量 |

## 2. 本议题必须产出的结论（缺一不可）

| 项 | 形式 |
|---|---|
| `S1-01` 目标用户与优先级 | 排序列表 |
| `S1-02` 首要待办任务（一句话） | 一句话 |
| `S1-03` 真实失败模式（承诺型 / 找不到型 / 都有） | 单选或权重 |
| `S1-04` 永久不可承诺清单 | 条目列表 |
| `S1-05` 可测验收指标（≥1 条） | 可测量表述 |
| `S1-06` **方案决策**：做（含试点范围） / 不做（仅增强 P38） | 二选一 + 理由 |
| `S1-07` 失败判据（什么时候该撤） | 表述 |

`S1-06` 即此前 TL 提出的 A/B 选择——**由业务代表判定，不由 TL 判定**。

## 3. 会后流程

```text
台阶 1（本清单）→ 业务代表签字
   ↓
台阶 2《产品知识口径与门禁规则》→ 业务 + 知识架构 Owner 签字
   ↓
台阶 3《设计说明与影响面》→ 智能体 QA 独立评审
   ↓
TL 创建 Loop（含 scope / gates / exit criteria）→ 声明切换 feature_pilot 后实现
```
