## 1. 审查背景与目标

### 1.1 触发原因

P24 DKWS 供应链重构移除了 `adapters/knowledge-filesystem/` 适配器（含 17 个 Java 源文件 + 12 个测试文件），但项目中仍有大量文档、合同声明、Loop 记录引用已删除的组件和路径，与当前代码实现形成矛盾。同时，V1.0→V1.1 迁移后遗留的旧路径引用（`scenario_data/` → `scenario/seed/`）和从未实现的模块声明（`modules/skill-runtime`、`adapters/mock-rag`）仍散布在权威源中。

### 1.2 审查目标

1. **消除合同-实现矛盾**：specs 权威源中声明的路径必须与实际代码一致
2. **标注历史文档**：无法删除的历史记录（已关闭 Loop、已交付文档）添加架构审查标注
3. **清理孤立文件**：删除已无任何消费者引用的过时文件
4. **建立适配器状态追踪**：明确标注哪些适配器已实现、哪些待实现、哪些已移除

### 1.3 审查原则

| 原则 | 说明 |
|------|------|
| **合同 SSOT 不可破坏** | specs 中的合同声明（`activation.adapter`）是意图声明，"未实现"≠"声明错误"，不删除只标注 |
| **历史记录只标注不篡改** | 已关闭 Loop 的 scope 记录是历史事实，不回改内容，只加注释说明当前状态 |
| **实现代码为准** | 文档与代码矛盾时，以代码为准，文档添加审查标注 |
| **最小侵入** | 优先添加标注而非重写文档，保留原始信息供回溯 |
