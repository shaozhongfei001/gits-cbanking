## 4. 派工方案（WP01–WP07，建议书 §15.4）

建议书 §15.4 定义了 7 个工作包。我按**依赖关系**排布为 5 波：

```
Wave 1（并行，无依赖）
  ├─ WP01 范围与映射 ──── 我（TL）
  └─ WP02 行业与经营知识 ── SubAgent: knowledge-researcher（KERT 侧）

Wave 2（并行，依赖 WP01 的 ID 体系）
  ├─ WP03 指标与规则 ────── SubAgent: metric-owner
  └─ WP04 产品知识 ──────── SubAgent: product-knowledge-owner

Wave 3（依赖 WP02/WP03/WP04 的固定版本）
  └─ WP05 能力与地图 ────── SubAgent: capability-engineer

Wave 4（依赖 WP05）
  └─ WP06 业务证据与预览 ── SubAgent: integration-engineer（L4-1 仅证据接口）

Wave 5（依赖全部）
  └─ WP07 验收包 ────────── SubAgent: independent-qa（**不得由我代签**）
```

### 4.1 各工作包完成定义（建议书 §15.4 原文要求）

| 包 | 交付 | 完成定义 |
|---|---|---|
| **WP01** | 一页任务范围、三仓锚点、旧新对象及消费者对照 | 无"同名自动兼容"；既有受保护合同有差异说明 |
| **WP02** | 一个行业方案包、经营模型卡、可引用原文 | 八维各有适用判断；客户关联有证据；未知明确 |
| **WP03** | 首期 MetricSpec、六类规则子集、SIM 参数和正反例 | 输入、单位、窗口、公式、合法解释和结果**均可复算/判断** |
| **WP04** | 产品条款、解释、体检、条件矩阵和互斥对象 | **不以抽象规则 ID 代替条件内容** |
| **WP05** | 真实提供者、端口绑定、计划编译及语义探针 | 必需节点**真调用**；缺失、歧义、越权**明确失败** |
| **WP06** | 证据接口；完整试点实现 P12/P13/P14 | 人工可补充排除锁定，变更后产物及确认版本正确 |
| **WP07** | 固定案例、期望、实际输入输出、trace、限制与缺陷 | 定义/运行/业务结论**分开**；**无伪独立 QA** |

### 4.2 依赖硬约束（建议书 §15.4 末句）

> 「WP02–WP04 可以由对应责任团队独立准备，但 **WP05 必须消费它们的固定版本**。
> **只有前序输入达到合同要求，才进入整体运行验收。**」

→ 故 **Wave 3 不得在 Wave 2 未固定版本时开工**。这是硬门禁。
