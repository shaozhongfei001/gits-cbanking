## 0. 一句话结论

- **现状**：`MetricDefinition.full.schema.json` 的 **7 组合同 schema 齐备**（42 必填字段），
  但**实际定义只有 1 项**（`SIM.METRIC.CUSTOMER_AVG_DEPOSIT@1.0.0`，`status=CANDIDATE`）。
- **`RuleSpec` 完全不存在** —— 13 字段无任何文件承载。
  现有规则形如 `{"id","name","rule"}` 三字段，或 `{"id","condition","action","talkTrack"}` 四字段。
- **首批必需指标 15 项**（按 §7.4 规则子集反推），其中当前夹具可直接复算约 8 项。
- **三个关键设计决策**（对应建议书纠正我的三点）：
  1. **W-4（被低估）**："能否比较"做成**先于解释的硬前置**
  2. **四类结果分维度表达**，**营收↑纳税↓不判 FACT_CONFLICT**
  3. **缺数据用五维表达**，不用单个 `missing=true`

#### M08 应收账款周转天数【设计】

| 组 | 内容 |
|---|---|
| 身份 | `SIM.METRIC.AR_TURNOVER_DAYS@1.0.0`，Owner `SIM-METRIC-OWNER` |
| 对象与粒度 | `entityType: Customer`；`baseGrain: periodStart+periodEnd+Customer`；`aggregationGrain: CustomerPerPeriod` |
| 计算 | `平均应收 / 同期赊销收入 × 期间天数`；**无赊销收入时另立 `…_PROXY` 版本**，标 `PROXY`，**不得同 ID 静默替换**（§6.2 原文） |

#### M21 授信使用率【设计】

| 组 | 内容 |
|---|---|
| 计算 | 同额度池内已占用额度 / 当时有效额度 |
| **关键约束** | **循环、共享、产品子限额不重复相加**；**分母为零返回 `NOT_APPLICABLE`** |
| 输出 | 百分比，`precision: 2` |
| 失败行为 | 分母为 0 → `NOT_APPLICABLE` + 原因；额度池边界不明 → `UNKNOWN` |

#### M13 现金转换周期【设计】

| 组 | 内容 |
|---|---|
| 计算 | `M08 + M10 − M12`（三者须**口径兼容**） |
| **关键约束** | **可为负**；**不能因负值直接判断有错误**（§6.2 原文） |
| 失败行为 | 任一组分 `UNKNOWN` → 整体 `UNKNOWN`（**不得跳项计算**） |

### 2.3 缺数据的五维表达（§6.5，强制）

**禁止**用一个 `missing=true` 代替全部原因。每项数据产品须分别返回：

| 维度 | 取值 |
|---|---|
| `availability` | 该数据产品是否存在 |
| `authorization` | 本任务是否有授权 |
| `coverage` | 覆盖比例（如本行可见比例） |
| `freshness` | 是否在新鲜度要求内 |
| `retrievalOutcome` | 本次获取结果 |

**业务值三态**：`KNOWN` / `UNKNOWN` / `NOT_APPLICABLE`
**执行结果四态**：`SUCCESS` / `PARTIAL` / `FAILED` / `NOT_RUN`

> **核心区分**（§6.5 原文）：**没有执行过的"无冲突"与检查成功且未发现冲突必须区分。**

## 3. 六个 RuleSpec 完整 13 字段定义

### 3.1 统一执行顺序（§7.2 六步，强制）

```
1. 校验实体匹配、口径、窗口、单位、授权及数据覆盖
2. 判断行业和业务模式是否适用；不适用则停止该规则
3. 对齐期间，处理季节性、基数及结构变化；不能对齐则返回不可比较
4. 执行批准的公式、阈值和条件，生成候选信号
5. 检查已有的合理解释及反证，区分"解释已验证"与"仅有解释假设"
6. 生成带证据、条件、优先级和下一步的结果；执行权限独立检查
```

**注意步骤 3 的强制语义**：**不能对齐 → 返回"不可比较"，而不是"无异常"**。这是 W-4 的核心落地。

### 3.2 可比性前置检查清单（W-4 落地，先于一切解释）

| # | 检查项 | 不通过时的输出 |
|---|---|---|
| C-1 | **同主体**（法人 ID 一致，非集团/单体混用） | `NOT_COMPARABLE` |
| C-2 | **同概念**（营收 vs 开票 vs 回款 vs 结售汇**分别建模**） | `NOT_COMPARABLE` |
| C-3 | **同期间**（所属期一致，非开票日 vs 收入所属期混用） | `NOT_COMPARABLE` |
| C-4 | **同单位**（币种、金额单位一致） | `NOT_COMPARABLE` |
| C-5 | **同覆盖范围**（本行可见 ≠ 企业全量） | `PARTIAL` + 覆盖说明 |
| C-6 | **同口径版本**（报表单体/合并、审计状态一致） | `NOT_COMPARABLE` |
| C-7 | **授权有效** | `NOT_AUTHORIZED` |
| C-8 | **时点可知**（`availableAt ≤ asOf`，**防时间泄漏**） | `FUTURE_DATA_FORBIDDEN` |

> **W-4 的正确理解**（建议书 §16.2 原文）：
> 「不仅是误报，**部分输入根本不可比**；**先阻止错误比较再解释**。」
> → 故 C-1~C-8 **不是**解释的一部分，而是**规则的前置门禁**。

### 3.3 R01 同事实一致性

| 字段 | 内容 |
|---|---|
| `appliesWhen` | 同一主体、同一概念、有效期重叠、单位一致、语义版本可比 |
| `requiredInputs` | 同概念 ≥2 个来源的同期间值 + 各自 `sourceVersion` |
| `comparability` | C-1~C-8 全部通过 |
| `window` | 同期间 |
| `baseline` | 无（同事实对照，非趋势） |
| `predicate` | 存在两个来源值 `v1, v2` 满足 `\|v1 − v2\| / max(\|v1\|,\|v2\|) > 0`（**严格不等即冲突，容差待核**） |
| `thresholdProfile` | `SIM-PARAM-R01-DIFF-TOLERANCE`（**待定，不得默认 0**） |
| `explanations` | 来源有明确替代关系（如新版本报表）→ **优先用新版但保留旧证据**（**不静默取平均**） |
| `outcome` | `FACT_CONFLICT` |
| `priority` | `P1`（最高，事件优先展示） |
| `dedupKey` | `customerId + concept + period + sourceVersionPair` |
| `cooldown` | 无（同事实冲突须持续可见） |
| `failureBehavior` | 可比性不通过 → `NOT_COMPARABLE`；来源版本缺失 → `UNKNOWN` |

### 3.4 R03 收入、经营回款与应收变化

| 字段 | 内容 |
|---|---|
| `appliesWhen` | 企业收入与本行观察范围**明确**；至少一个可比窗口 |
| `requiredInputs` | M01（营收）、M17（本行可识别经营收款）、M07/M08（应收） |
| `comparability` | **必须声明本行观察范围**；`coverage` 须返回 |
| `window` | 最近 3 个**完整**月；同比需存在上年对应月份 |
| `baseline` | 基期金额 ≥10 万元（**低于此不启用趋势判断**） |
| `predicate` | 存在指标相对变化超 `±20%` **且**方向不一致 |
| `thresholdProfile` | `SIM-PARAM-TREND-20PCT` |
| `explanations` | ①渠道变化 ②主要客户账期变化 ③结算方式变化 ④季节性 —— **均须有证据才降低信号** |
| `outcome` | `BUSINESS_ANOMALY`（**默认**）；仅在**同事实明确矛盾**时才是 `FACT_CONFLICT` |
| `priority` | `P2` |
| `dedupKey` | `customerId + rule + window + primaryEvidence` |
| `cooldown` | `SIM-COOLDOWN-30D`（**期间状态或重要证据变化则重评**） |
| `failureBehavior` | **无跨行资料 → 不得认定"他行分流"**（§7.3 原文）；`coverage` 不足 → 输出调查问题，**不输出"矛盾事实"** |

### 3.5 R06 增长与营运资金占用

| 字段 | 内容 |
|---|---|
| `appliesWhen` | 财务窗口一致；应收、存货周转**可计算** |
| `requiredInputs` | M01, M06, M07, M08, M09, M10, M11, M12, M13 |
| `comparability` | 财务期间一致；**周转指标口径兼容**（M13 组分不可跳项） |
| `window` | 同口径财务窗口 |
| `baseline` | 同比或上期 |
| `predicate` | **应收周转增加 ≥15 天 且 相对增幅 ≥20%** |
| `thresholdProfile` | `SIM-PARAM-AR-DETERIORATE-15D20PCT` |
| `explanations` | ①行业账期普遍延长 ②客户结构变化 ③年末冲量 —— 须有行业证据 |
| `outcome` | `BUSINESS_ANOMALY` |
| `priority` | `P2` |
| `dedupKey` | `customerId + rule + window` |
| `cooldown` | `SIM-COOLDOWN-30D` |
| `failureBehavior` | **不自动推算可授信额度**（§7.3 明文）；周转不可算 → `NOT_APPLICABLE` |

### 3.6 R08 逾期/欠息事件与额度占用

| 字段 | 内容 |
|---|---|
| `appliesWhen` | 事件有效；源版本和状态明确 |
| `requiredInputs` | M22（逾期本金）、M23（欠息）、M21（授信使用率） |
| `comparability` | 事件须**源系统认定**，**不由 LLM 推测**（§6.2 原文） |
| `window` | 截止时点 |
| `baseline` | 无（事件型） |
| `predicate` | `逾期本金 > 0` **或** `欠息 > 0`（**独立触发**） |
| `thresholdProfile` | `M21 ≥ 90%` 仅作**附加严重性信息** |
| `explanations` | 无（**风险事件不接受解释关闭**） |
| `outcome` | `RISK_EVENT` |
| `priority` | `P1` |
| `dedupKey` | `customerId + eventId` |
| `cooldown` | 无 |
| `failureBehavior` | **低占用逾期仍必须显示**（E04）：**不得因使用率未满而不显示** |

> **W-5 落地**（建议书 §16.2）：**自动内部提示可被授权；正式认定、处置及责任独立。**
> 即 R08 可**自动产生内部关注事项**，但**正式风险认定/调级/冻结额度不由本系统执行**；
> 且「生成提示、投递、接收、确认、处置、关闭」**分别记录**，
> **不得把报告中出现"已预警"视为履行处置责任**（§7.6 原文）。

### 3.7 R12 客户需求与服务覆盖

| 字段 | 内容 |
|---|---|
| `appliesWhen` | 真实业务量 + 现有服务覆盖 + **明确客户需求或待核实假设** |
| `requiredInputs` | M19（代发覆盖人数）、M20（代发金额）、M15（到期债务） |
| `comparability` | **同主体**（集团 vs 子公司须核对）；同工资所属期 |
| `window` | 同工资所属期 |
| `baseline` | **经确认同主体员工 ≥100 人** |
| `predicate` | `代发覆盖 < 50%` **且有授权需求资料** |
| `thresholdProfile` | `SIM-PARAM-OPPORTUNITY-COVERAGE-50PCT` |
| `explanations` | 无（机会规则） |
| `outcome` | `OPPORTUNITY` |
| `priority` | `P3` |
| `dedupKey` | `customerId + rule + period` |
| `cooldown` | `SIM-COOLDOWN-90D` |
| `failureBehavior` | **未知覆盖不能当 0%**；**不得只按本行中收排序**；**不得导出员工个人营销名单** |

## 4. 四类结果的判定边界（§7.1）

| 类型 | 定义 | 例 | 允许后续 |
|---|---|---|---|
| `FACT_CONFLICT` | **同主体、同概念、同期间**等可比前提下，资料出现**不能同时成立**的值或陈述 | 两份**同版本**报表同一科目不同值 | 回源核实、保留双方证据；**不静默取平均** |
| `BUSINESS_ANOMALY` | 与基线、季节性或可解释关系明显不同的观察 | 可比期间回款下降、账龄拉长 | 提出假设、替代解释、资料与问题 |
| `RISK_EVENT` | 权威来源记录的事件或受控规则产生的风险关注事项 | 已认定的逾期、被执行 | 展示事件及适用处置规则；**与正式认定和处置状态分开** |
| `OPPORTUNITY` | 有客户经营依据、尚待确认的服务需求 | 新增员工而现有代发覆盖较低 | 准备讨论方向与条件核验，**不自动销售** |

### 4.1 必须明确的判定例证（§7.1 原文）

> 「**营收上涨而纳税下降一般不能直接构成 FACT_CONFLICT。**
> 两者可能分别真实，关系受到**税种、税收优惠、扣除、结算和时点**影响。
> **只有对相同事实的明确矛盾，才使用"事实冲突"。**」

据此明确：

| 情形 | 正确类别 | 错误类别（我方原设计） |
|---|---|---|
| 营收↑ 且 纳税/开票↓ | `BUSINESS_ANOMALY`（有合法解释支路） | ~~`FACT_CONFLICT`~~ / ~~TO_VERIFY 一刀切~~ |
| 社保人数↑ 且 代发薪↓ | `BUSINESS_ANOMALY` + `OPPORTUNITY` | ~~矛盾~~ |
| 用电↓ 且 营收↑ | `BUSINESS_ANOMALY`（**须先验可比性**） | ~~矛盾~~ |
| 使用率趋满 且 逾期 | `RISK_EVENT`（**逾期独立触发，使用率仅附加**） | ~~"背离"~~ |
| 两份同版本报表同科目不同值 | `FACT_CONFLICT` | ✅ 原设计正确 |

**根本纠正**：我方原 4 条 `SIM-XC-*` 把四类不同信号统一叫"**背离**"并统一处置为"标待核实"，
**混淆了 R01（事实冲突）与 R03/R05（经营异常）**。这是 Q2.3 的实质问题。

### 4.2 R02 的双支路要求（§7.3 明文）

> 「**两条分析支路，不能"纳税/开票"混算**」

→ 原 `SIM-XC-1` 写「营收↑ 但**纳税/开票额**↓」把两个不同概念合并，
**违反 §2.3「营收、开票、实缴税款、经营回款…分别建模」**。
必须拆为：`R02a` 营收-开票、`R02b` 营收-实缴税款。

### 4.3 R05 的适用前提（§7.3 明文）

> 「适用**制造业务**，生产边界、产品组合和外包可解释」

→ 原 `SIM-XC-3`（用电-营收）**无条件适用于所有客户**，
**违反 §5.3「用电量…不能成为服务业、贸易类企业的必填经营活力指标」**。

## 5. SIM 参数包（§7.4）

> **重要声明（§7.4 原文）**：以下数值是「**测试行为所需的专家建议参数**」，
> **不是行业公认预警阈值**。参数包必须**版本化**，明确适用的 SIM 行业和数据集。

| 参数项 | 首轮 SIM 值 | 我方理解 | 参数 ID |
|---|---|---|---|
| 截止时间 | 每次任务固定 `asOf`；**禁止使用之后才发布的资料** | 防时间泄漏 | `SIM-PARAM-ASOF-PIN` |
| 月度观察 | 最近 **3 个完整月**；同比需存在上年对应月份 | 只有 30 天数据时不启用同比规则 | `SIM-PARAM-WINDOW-3M` |
| 一般趋势阈值 | 相对变化 **±20%**，且基期金额 **≥10 万元**；人数基期 **≥20 人** | 避免小基数夸大 | `SIM-PARAM-TREND-20PCT` |
| 周转恶化 | 应收周转**增加 ≥15 天**，且相对增幅 **≥20%** | 兼顾绝对与相对 | `SIM-PARAM-AR-DETERIORATE-15D20PCT` |
| 授信趋满 | 同额度池使用率 **≥90%** | **仅描述占用**，不单独定义逾期或违约 | `SIM-PARAM-UTIL-90PCT` |
| 逾期事件 | 本行权威 SIM 事件有效、逾期本金>0 或欠息>0 | **不依赖授信使用率**，避免漏掉低占用逾期 | `SIM-PARAM-OVERDUE-NONZERO` |
| 机会规则 | 经确认同主体员工 **≥100**、代发覆盖 **<50%**，并有授权需求资料 | **未知覆盖不能当 0%** | `SIM-PARAM-OPPORTUNITY-COVERAGE-50PCT` |
| 去重 | 相同客户、规则、观察窗口及主要证据合并 | **不把同一新闻多次转载生成多个关注事项** | `SIM-PARAM-DEDUP` |

**附加约束**（§7.4 末段）：
- **去重只合并展示，不删除追踪责任**
- 冷却期内若**事件状态或重要证据变化**，**必须重评**

## 6. 负向规则清单（§7.2 / Q2.6）

> 要求：**解释须有证据，不能用模型编造解释压掉异常**（§7.2 原文）

| # | 负向规则 | 抑制的对象 |
|---|---|---|
| N-1 | **税收优惠**（有覆盖该期间的有效证据） | R02 营收-税款信号 |

| N-5 | **季节停工**（有历史季节性数据） | R05/R06 |

## 7. 六个验收案例（§7.5）

| 案例 | 已知输入 | 正确结果 | **不允许的结果** |
|---|---|---|---|
| **E01 增长占款** | 同口径收入增长 25%，应收周转由 60→90 天，现金流转负 | 经营异常与周转需求假设；询问账期、客户和回款 | **直接给贷款额度**；**称"企业造假"** |
| **E02 合法税务差异** | 营收增长，实缴税款下降；**有覆盖该期间的有效优惠证据** | **解释**税款变化；保留其他未核实因素 | **不经税种和期间核对便报"营收不实"** |
| **E03 能源边界变化** | 用电下降，**外包生产增加且有依据**，收入增长 | **标明原能耗代理失去可比性** | **将用电下降等同停产** |
| **E04 低占用逾期** | 使用率 **35%**，源系统**存在当前逾期事件** | **仍显示逾期及需核实事项** | **因使用率未满而不显示** |
| **E05 代发机会** | 同主体员工 **120 人**，本行覆盖 **36 人**，需求授权有效 | 覆盖率 **30%**，生成代发沟通方向 | **将未覆盖 84 人全部认定为可营销个人** |
| **E06 无法判断** | 本行回款下降，企业财务和其他银行资料**均不可得** | **说明本行观察变化**，提出渠道核实问题 | **确认"企业营收下降"或"已流失到他行"** |

**E04 特别注意**：它**同时**验证 R08 的独立触发（不依赖 M21）**和**"低占用不等于低风险"。
这正是 Q2.4「自动升级」问题的答案落点。

## 8. 时间泄漏防护（§12.4，W-漏项）

### 8.1 必须同时记录的六个时间戳

| 时间戳 | 含义 |
|---|---|
| `eventTime` | 事件实际发生时间 |
| `period` | 所属期 |
| `sourcePublishedAt` | 来源发布时间 |
| `availableAt` | **本系统可获得时间** |
| `ingestedAt` | 入库时间 |
| `asOf` | 任务截止时点 |

**硬约束**：`availableAt ≤ asOf`，否则 `FUTURE_DATA_FORBIDDEN`。

### 8.2 现有夹具的正确处置（**这是我此前漏掉的问题**）

现状：`SIM.METRIC.CUSTOMER_AVG_DEPOSIT.json` 的
`expectedValue.period = {from: 2026-09-01, to: 2026-10-01}`（**完整 30 日**）。

**问题**：在真实日期 **2026-09-12** 的访前包中，**不得**把它作为"本月已完成实际日均"呈现。

**正确处置**：
1. **保留**该夹具作**离线回归参照**（值 `2983333.33` 不变）
2. 真实日历演示**改用已完结月份**，或独立定义的 **MTD** 口径
3. MTD 必须**单独标注**，**不能冒充整月**（§6.2 原文：「未完结月份须单独标注 MTD」）
