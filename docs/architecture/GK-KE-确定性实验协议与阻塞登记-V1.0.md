## 2. 实验协议（**预注册 · 环境就绪即可执行**）

> **预注册的含义**：判定标准**先于执行锁定**。下述通过/失败判据**不得在看到结果后修改**。

### 2.1 目的

> **回答一个问题：下游能力能否被固定到确定性？**
>
> 该答案决定判据的**根本范式**（见 §4），因此必须在起草任何新判据**之前**得到。

### 2.2 输入构造（**须逐字节固定并落盘**）

| 项 | 值 |
|---|---|
| 能力 | `bank-front-kyc-gap-check`（`SK-FRONT-006`） |
| 输入 | **固定一份** `customerId` + `upstreamStatus` + `conflicts`（**含具体 `ruleId`，非占位符**）；原始输入**逐字节落盘** |
| 调用次数 | **k = 5** |
| 参数 | `temperature = 0`、`seed` 固定（如支持）；**记录实际生效值**（须从服务端回读，不得只记请求值） |
| 其他 | 同一 `requestId` 不得复用（幂等缓存会伪装成确定性 —— **这是已知的假阳性来源**） |

### 2.3 记录要求（**缺任一项即实验无效**）

1. 实际生效的 `temperature` / `seed` / `model` / `model_version`（**从服务端回读**）
2. 5 次**原始输出全文**（不是摘要）
3. 排除字段（`generatedAt`）后的**规范化比较结果**
4. 每次调用的时间戳与 `requestId`

### 2.4 ★ 预注册判据（**不得事后修改**）

| 结论 | 条件 |
|---|---|
| **确定性可达** | 5 次输出**排除 `generatedAt` 后完全一致** |
| **确定性不可达** | 存在任意两次不一致 |
| **实验无效** | 实际 `temperature` ≠ 0，或未取到 seed，或**服务端未回读参数**，或 **5 次中任一次为空/报错** |

> **并须同时排除假阳性**：若发现"5 次一致"，必须再用**改动一个无关字符的输入**复跑，
> 确认输出**确实会变** —— 否则可能是**幂等缓存**造成的假确定性。

### 2.5 执行入口（环境就绪后一键运行）

```bash

export KERT_LLM_BASE_URL=… KERT_LLM_API_KEY=… KERT_LLM_MODEL=…

# 2) 确认参数可生效（B2 未解决则此步失败，实验应中止而非降级）

# 3) 运行（脚本待写：scripts/gk_ke_determinism_probe.py）
```

> **脚本尚未编写**，因为**未解决 B2 时写它没有意义**（写出来也只能跑 0.3）。
> **但协议已锁定** —— 这一点是刻意的：**先定判据，再执行**。

### 3.2 ★ 新发现：一个门禁**失败一次后自己变通过**

**已稳定复现**：
```
make generate && make check
    → [FAIL] contract-examples  exit=1   →  gk-ke-gates: FAIL (1 项完整性失败)

python3 scripts/run_gates.py --only contract-examples
    → [PASS] contract-examples  exit=0
```

**同一门禁、同一制品、同一会话，紧邻两次执行结论相反。**

> **"失败一次即自愈"的门禁比永远通过的门禁更危险。**
> 永远通过会被发现是假的；**偶发失败会被归因为 flaky 并被忽略**，
> 而它可能**每次都真失败一次**。
>
> 这是本系列同一根因的**第四个变体**：
> 恒真判据 → 永不失败的门禁 → 静默跳过的检查器 → **状态依赖的门禁**。

**状态**：**未定位根因**（本次预算耗尽），已登记为待办。
**未处置即不得声称 `make check` 的结论可靠。**

**事实三（附带发现的真缺陷，已修）**

**已修**：该字段与上游 `executionStatusReason` 一并改为**无条件必填**（合同 + SKILL.md 共 8 处）。
**根因**：**我改了合同，却没有检查"谁在强制它"。**
