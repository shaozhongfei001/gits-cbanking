## 四、改进方案：**把"确认"改成"反驳"，且强制在机器上**

> **总原则**：**任何我不能用一条"会失败的检查"证明的结论，不得表述为已完成。**

### C1 · 事实性断言必须附「穷尽检索凭证」

**规则**：任何 `存在/不存在/已交付` 断言，必须给出**三件套**：
`检索范围` + `检索式` + `命中数`。**缺任一项即视为未核实。**

**机器化**：`scripts/claim_audit.py`
- 断言以结构化条目写入交付文档：`{id, statement, type: EXISTS|ABSENT, scope, query, expect}`
- 脚本**重跑检索**并核对；不符即失败
- **反例测试**：故意缩小 `scope`（把"仓库"改成单个目录）→ 脚本必须失败
- **针对**：形态 ①（FAIL-43 就是 scope 只搜了仓库外）

### C2 · 检查器必须**自证覆盖**（计数守恒 + fail-closed）

**规则**：任何"遍历制品逐条检查"的检查器，**必须**输出
`发现条目数` 与 `已检查条目数`，**两者不等即失败**；
解析失效（条目数为 0 或低于下限）**必须 fail-closed**。

**机器化**：推广为**所有检查器的强制模板**（现有两个审计已实现，其余待补）
- **反例测试**：注入一条"落在跳过分支"的条目 → 检查器必须失败
- **针对**：形态 ②（FAIL-22/36 都是缺这一条）

### C3 · 无负例测试的门禁，其 PASS **不予采信**

**规则**：每个门禁必须能回答："**注入一个已知缺陷，它会不会失败？**"
**答不出 → 该门禁的 PASS 记为"未验证"，不得作为证据。**

**机器化**：`make gate-selftest`
- 对每个门禁注入一个已知缺陷，要求其**失败**（失败即 selftest 通过）
- 覆盖：`run_gates` 各项 + 两个判据审计 + `loop-guard`
- **反例测试**：把某个门禁改成恒返回 0 → selftest 必须报"该门禁无判别力"
- **针对**：形态 ②、**并且这是唯一能防"检查器自己坏了"的机制**

### C4 · "已修复"必须附「回读证据」

**规则**：声明修复时，必须给出**修复前后同一检查的输出对比**，
**且该检查自身已通过 C3**。

**机器化**：纳入交付模板 —— 无前后对比的"已修复"表述**不得出现在交付物中**
- **针对**：FAIL-29、FAIL-32（"声称修好实际没修"）

### C5 · 变更必须做**反向检索**

**规则**：改动 X 后，必须检索**"依赖 X 的全部位置"**（而非"X 的位置"），
并逐项确认或标注"不适用"。

**机器化**：变更后自动生成"被改项的全部引用位置"清单，要求逐项处置
- **针对**：FAIL-30/34/37/44（只更新新事实、不清旧表述）

### C6 · 合同变更**三问**（强制填写）

新增/修改任何合同字段，必须回答：
1. **谁生产它？**（模型 / 代码）
2. **谁强制它？**（校验器 / 测试 / 无）
3. **强制是**无条件**还是**有条件**？（有条件的必须与运行时一致）

**机器化**：KERT 侧增加一致性测试 —— `schema_keys` 的"无条件必填"语义
与合同文字声明的**必须一致**，不一致即失败
- **针对**：FAIL-44（我把条件必填写成合同，运行时却无条件强制 → 技能 1/4 概率失败）

### C7 · 工具代码**与制品同权**

**规则**：
- 编辑脚本**禁止 index 计数定位**，必须用**结构定位**（行前缀 / AST）
- 改完**先 `ast.parse` 自查**再执行
- **工具写入受控制品时，写权限与人的写权限同权** →
  `--fix` 类写回分支**在非作者身份下默认禁用**

**针对**：FAIL-26/35/42
