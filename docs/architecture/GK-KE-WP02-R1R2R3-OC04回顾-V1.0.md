## 二、R-1 / R-2 / R-3

### 2.1 R-1 能力三方闭合

**修复前**：地图引用 **9** 项 / 注册中心 **1** 项 / 设计文件 **4** 项 → **不闭合**

**真实性质**：**不是数据缺失，而是数据未同步**。
`map_spec.json` 里**本来就有**就绪度与证据行号，只是注册中心没同步。

**修复后**：注册 **10 项**（9 地图引用 + `SIM-CAP-INTERPRET`）

### 2.2 本次最重要的设计决策

> **10 项中只有 1 项 `callable: true`。**

4 项标着 `IMPLEMENTED*`，但**全部 `callable: false`** —— 因为 `probeStatus` 都是 `NOT_RUN`。

**依据建议书 §9.4**：「健康检查不能只验证 HTTP 200，**至少使用一个已知语义样例**」

**固化原则**：**`IMPLEMENTED`（有代码）≠ `callable`（可运行）**
→ 防止下游把"有代码"误读为"可运行"。

另为 9 项各加 `mustNotClaim` 字段，把建议书的禁止条款**写进合同**。

## 四、缺失数据补全方案

### 4.1 建议书对模拟数据的**硬要求**（§12.1）

数据必须分**三层**，且**评测答案须与检索语料物理或逻辑隔离**：

| 层次 | 内容 | 谁能访问 |
|---|---|---|
| **世界真值** | 企业关系、真实经营事件、准确账务、合理解释、隐藏缺口 | 构造与验收角色；**不直接给被测智能体** |
| **观察资料** | 行内表、报表、发票、行业报告、访谈、新闻、不同来源及误差 | 按场景、权限和时间开放 |
| **评测答案** | 应触发信号、允许结论、禁止结论、必要问题、标准计算 | 评测角色；**与语料隔离** |

**§12.2 原文约束**：
> 「模拟行业报告若写有"统计局""监管规定"等表述，
> **必须区分真实公开引用和虚构场景内容，不能伪造监管机构发布了某条模拟政策。**」

→ **我方遵守**：生成的数据一律使用 **SIM 命名空间**，**绝不再现真实监管机构署名**。
