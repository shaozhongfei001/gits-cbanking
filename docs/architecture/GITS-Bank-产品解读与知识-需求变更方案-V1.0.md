## 2. 变更提案

### 2.1 IA 归位（**不涉及合同**）

| 菜单 | 现状 | 提案 | 依据 |
|---|---|---|---|
| 知识与治理 › **产品解读与知识** | label=产品解读与知识，指向 P38 `/knowledge-map`，`key` 仍是 `evidence` | **指向"产品解读"页**（§2.2 的 v2） | 业主 09-14 决定 |
| 知识与治理 › 审批与审计 | `/approvals` | 不动 | — |
| 客户经营 › **产品推荐** | `/recommendation/:runId` | **接收 P38 的"知识卡与产品适用边界"能力**（去重后） | 业主 09-14 决定 |
| **P37 Claim/Evidence 中心** | 路由在（`/claims`）但**导航无入口（孤儿页）**，且 `listClaims` 运行期 404 | **本轮不动** | 业主 09-14 决定 |

**关于 P38 并入产品推荐（去重，不是叠加）**：产品推荐页已有
`ProductCandidateCompare`（候选对比）、`CustomerFactSnapshotPanel`（客户事实快照）、
`EligibilityResultPanel`（资格）、`ProductPortfolioPanel`（组合）、`RecommendationDecisionPanel`（人工决定），
与 P38 的"按客户装配 KE + 产品适用匹配"**重叠度高** ⇒ 必须先出**字段级去重表**再动手，
否则会做出"两套相似面板"。

### 2.2 产品解读页 v2（按截图重建 + 正式化）

```
[产品知识目录]  [产品摘要 + 原始文件路径]
 按 6 条线分组   [深度解读：11 章节（原始产品文档）]
                [制度解读：三视图 + 依据原文 —— 仅"已发布 Release"的产品]
```

- **数据来源**：KERT 产品卡（`version=` 目录）→ **需新增读取合同**；
- **忠实原则继承 PI-0**：`UNKNOWN` 不补值、字段带 `EvidenceRef` 回链、**不呈现未发布知识**；
- **"仅现金池有制度解读"是数据现状**（非产品差异）⇒ UI 应表达为"该产品是否有已发布 Release"，而非特例硬编码；
- **只读**（保持截图语义）；不引入任何写操作。

## 3. 「同业同类产品比对」：与现有红线**直接冲突**，三条路径请你选

`01_raw/_public_reference/README.md`（Loop PI-0 G0-3 建立）**明文**：

| 红线 | 原文要点 |
|---|---|
| 用途 | `usage: VERIFICATION_ONLY`，唯一合法用途是**验证解析器能读源材料**，不验证内容对不对 |
| 权威性 | **不得作为任何产品卡字段的权威依据**；引用本区证据的产品卡**永久停留 `CANDIDATE`，门禁自动阻断** |
| 门禁 | **永远不得支撑**本机构字段、`HardRule`、`INTERPRETATION_READY` 或 `RECOMMENDATION_READY` |
| 合规 C-2 | 仅内部研发解析验证、**不向外分发**；**不得将来源机构名称写入产品卡或 taxonomy 字段**；`institution` 统一 `DEMO-BANK` |
| 可复现性 | 来源 URL / 抓取方式 / 时点快照均 `UNVERIFIED`，标 `CONFLICTING_EVIDENCE`（`F-L00-10` 未闭） |

⇒ **按字面做"同业产品与我们产品并排作事实呈现"，与上表逐条冲突。**

| 路径 | 做法 | 前提/代价 | 我的建议 |
|---|---|---|---|
| **A. 只做本行产品间对比** | 用产品卡**第 6 章「前置、互斥、替代与配套产品」**做**本行产品**对比矩阵（互斥/替代/配套） | **无新合规风险**；数据已在 13 张卡里 | ✅ **建议先做这个** |
| **B. 公开参考只读展示（脱敏）** | 同业资料以「**公开参考（非权威）**」明确标注呈现：去机构名、不进门禁、不参与 READY 判定、标注来源未验证 | 需你**明确豁免** `VERIFICATION_ONLY` 的**展示**口径；`F-L00-10` 来源补证仍需推进 | 可行，**须你签字** |
| **C. 真做同业产品事实比对** | 需：权威同业数据源 + 授权 + 新字段 + 新合同 + 新门禁规则 | 最重；涉第三方资料合规与对外分发边界 | **现阶段不建议** |

**我不做的事情**：不自行解除 `_public_reference` 红线、不把公开参考内容写进任何"事实"字段、不发明合同未定义的字段。
