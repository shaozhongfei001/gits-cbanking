## 2. 两个**最值得注意**的发现（执行者提出）

### 2.1 S3 的失败形态是「**文本说对、结论说错**」

**执行者的实证**：

> V1.1.0 的 S3 输出中，`warnings` **确实**出现了语义上符合要求的措辞：
> 「规则覆盖不足……覆盖状态待核实」「事实对账未执行：reconciliationStatus = NOT_RUN」
> **但同一份输出的结论字段 `kycGaps` 是空的。**

**→ 若采用"关键词出现即算满足"的文本启发式，S3 会被判 PASS。**

**这证伪了判据 §1.3 登记的「道路 2：退化为文本启发式」** —— 至少不能采用"关键词出现"这一形式。

**这也是判据 §2 预言的形态**：「最容易被『看起来对』糊弄过去的一条」。

### 2.2 S2 的 `PASS` 是**空转的**

**执行者的论证**：

> 该判据是**否定式**（"不存在…"）。任何**恒返回** `kycGaps: []` 的下游都**自动满足**它。
> → `PASS` 为空转，**不能**作为"下游理解了空结论"的证据。
>
> 判据 §2 自述「此条与 S3 成对，用于区分『真的没有』与『没查』」。
> **S3 未达成（FAIL）→ 该配对的目的是否达成。**

**→ 「2 个 PASS」的实质证据力远低于表面计数。**

## 5. 门禁层修正（响应执行者 7.8）

**执行者指出**：
- `make readiness` 的 docstring 称"未达成时非零退出"，**但实现恒返回 0**
- `semantic-consumption` **既不在 `make verify` 也不在 `make readiness` 清单中**
- → **B 层唯一剩余缺口只能靠人读门禁输出发现，不会被任何自动化路径阻断**

**我的修正**：

| # | 修正 |
|---|---|
| 1 | `run_gates.py` 新增 `--kind {integrity,readiness}` 与 `--strict` |
| 2 | `make readiness` 改为 `--kind readiness --strict` → **未达成时非零退出**（实测 `exit=2`） |
| 3 | `make integrity-check` 改为 `--kind integrity`（不再硬编码清单） |
| 4 | `semantic-consumption` 与 `chain-trace` **自动纳入 readiness**（按 kind 筛选，不会再漏） |
| 5 | **新增 `NOT_MET` 先于 `INCONCLUSIVE` 的分类优先级** —— 确定未达成**强于**无法判定，不得被降级显示 |

**并额外修了一处我自己的同类缺陷**：
`semantic-consumption` 脚本原先只看"是否已判定"，**不看判定结果** ——
5 条全判定后报 `已判定` 并 `exit=0`，
**使"判定为 2 个 FAIL"被显示为 PASS**。
这与刚修好的"INCONCLUSIVE 显示为 PASS"**是同一类缺陷**。
已改为按预注册规则汇总（任一 FAIL → `NOT_MET`）。

**实测**：
```
gk-ke-semantic-consumption: NOT_MET
  已判定: 5 / 5（判定由独立执行者作出，TL 未代判）
  判定计数: {'INCONCLUSIVE': 1, 'PASS': 2, 'FAIL': 2}
  **未达成** —— FAIL: ['S3_NOT_RUN_NOT_NONE', 'S5_REPRODUCIBLE']

make check        → 17/18，READINESS NOT MET: ['semantic-consumption']，exit=0
make readiness    → exit=2（未达成即非零）
```
