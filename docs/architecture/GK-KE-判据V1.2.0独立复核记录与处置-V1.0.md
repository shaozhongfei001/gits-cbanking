## 1. 【严重】对比式判据会被 LLM 非确定性假通过

### 1.1 复核者原文（**核心指控**）

> 两条判据本质是 `downstream(A).kycGaps ≠ downstream(B).kycGaps`。
> 但下游是 **LLM 能力**（`SK-FRONT-006`，工具 `T-LLM-001`）。
> 同一实测已证明：**同输入两次调用输出即不同**
> （S5 观测：runA=1 条 / runB=3 条，`priorityCategory` 相异）。
>
> **后果**：A、B 是两次独立调用，其输出差异**无法归因于"消费了上游"**，
> 完全可以由 LLM 随机性解释。
> → **S2(b)、S3(b) 在 A/B 输入即便完全相同的情况下也大概率"≠"→ 自动 PASS。**
>
> 这直接**复活了本版声称已消除的"空转通过"**。
> **S3(b) 更严重**：它还有方向性要求（`len(B)>len(A)`）。
> 若 A 与 B 仅因随机性就长度不同，**方向"恰好正确"的概率约 1/2**
> → S3 会被随机性**假通过**。

### 1.2 我的评估：**指控成立，且是本版最严重的缺陷**

我承认这是**设计级错误**，不是表述问题。

**我的推理错在哪**：我写 S2/S3 时的隐含前提是
「下游是确定性的 → A 与 B 的差异只能来自输入差异」。
但**这个前提我自己刚刚实测证伪过**（S5 = FAIL，报告就存在同一目录）。

> **我把一个已被自己证伪的假设当成了新设计的基础。**
> 这是本记录最重要的一条 ——
> **证伪过的假设必须被登记为"禁止使用"，而不只是"这次没通过"。**

### 1.3 我未登记的隐含依赖（复核者指出）

> S5 是确定性硬门槛，S2(b) 却把"跨场景输出必不同"当作消费证据。
> 二者对 LLM 的确定性假设**相互矛盾**。
> **若下游不满足 S5（本实测即如此），S2(b) 就退化为随机噪声判据。**
> 文档未声明"S2(b)/S3(b) 仅在 S5 PASS 时才有判别力" → **隐含依赖未登记**。

**评估**：成立。这会导致**在 S5 FAIL 的情况下仍单独报告 S2/S3 通过** —— 属归属错误。

## 2. 处置：V1.2.1 的修正设计

### 2.1 核心修正：**组内稳定性前置**

> **对比只有在组内稳定时才构成证据。**

修正后的对比判据结构：

```
对场景 X ∈ {A, B}，各调用下游 k 次（k ≥ 3）：

stable(X) := 若 k 次输出（排除允许字段、规范化后）**完全一致**，
             则该输出；否则 ⊥（不可判定）

对比判据通过 ⟺ stable(A) ≠ ⊥ ∧ stable(B) ≠ ⊥ ∧ stable(A) ≠ stable(B)
                ∧ 差异为**结构性**（见 2.2）
对比判据 INCONCLUSIVE ⟺ stable(A) = ⊥ ∨ stable(B) = ⊥
```

**关键变化**：
- 组内不一致 → **`INCONCLUSIVE`**（**不是** PASS）——
  因为此时 A/B 差异**不可归因**，既不能判通过也不能判违反。
- 这使"非确定性"从**静默的假通过来源**变成**显式的不可判定原因**。

**代价（须如实声明）**：在本实测条件下（S5 = FAIL），
**S2(b)/S3(b) 将判 `INCONCLUSIVE`** —— 即"无法用对比法证明消费"。
**这是正确结论**：**对一个不可复现的下游，对比法本身不成立。**

### 2.2 结构性差异要求（取代"长度不同"）

| 原 V1.2.0（弱） | V1.2.1（强） |
|---|---|
| `len(B.kycGaps) > len(A.kycGaps)` | B 中存在条目 `d`，使 `d.trigger` 或 `d.verifyScript.factBasis` **引用了 `U_B.dataGaps[].indicator` 或 `U_B.indicators[].name`** |

**理由**：长度差异可被随机性产生；**"引用了 B 场景特有的上游字段"不能** ——
因为 A 场景的上游输出里**没有这些字段值**。
这是**结构性证据**，不依赖"下游是否随机"。

### 2.3 登记隐含依赖（不再隐藏）

判据文档新增一节 **「判据间依赖登记」**：

| 判据 | 依赖 | 后果 |
|---|---|---|
| **S2(b)** | 需 `stable(A)` 与 `stable(B)` 存在 | 若下游非确定性 → `INCONCLUSIVE` |
| **S3(b)** | 同上 | 同上 |
| **S2(b)/S3(b)** | **在 S5 的组内稳定性意义上与 S5 同源** | 若 S5 FAIL，S2(b)/S3(b) 必然 `INCONCLUSIVE` |

**并明确**：**不得**在 S5 未通过时单独报告 S2/S3 的对比路径"通过"。

### 2.4 S3 的结构化路径（**现在成为主路径**）

复核者的发现使 **KERT 侧 R1 的重要性上升**：

> `coverageStatus` 是**结构化字段**，其取值**不依赖 LLM 随机性**。
> 因此 **S3(a) 是本判据唯一免疫非确定性的路径**。

S3(a) 判据：`downstream(B).coverageStatus == "NOT_RUN"` ∧ `downstream(A).coverageStatus == "SUCCESS"`

**→ 我将把 R1 从"增强"改述为"S3 可信判定的事实上唯一路径"。**
