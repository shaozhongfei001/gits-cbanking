## 3. ★ 三轮积累的「禁止使用清单」（**本文件最有价值的部分**）

> **这些不是建议，是被实测证伪的设计模式。**
> 依据纪律：**被证伪的假设必须登记为「禁止使用」，而不只是"这次没通过"。**

| # | 禁止的模式 | 证伪方式 |
|---|---|---|
| **A** | **判定键未经合同核对即使用** | 第 1 轮：5 条判据中 3 条的键在合同中**不存在** |
| **B** | **以自由文本作为机器判定键**（`warnings` 关键词、"人工看两段文字像不像"） | 实测：下游 `warnings` 正确写出"覆盖不足"，**结论字段却是空的** → 关键词启发式**假通过** |
| **C** | **以"跨场景输出差异"作为消费证据而不控制非确定性** | 第 2 轮：同输入两次输出即不同（1 条 vs 3 条）→ 差异可由随机性解释，判别力归零 |
| **D** | **测量装置把"答案"预先写入被测对象的输入** | 第 2 轮：采集器把 B 场景的缺项名写进下游输入，判据又要求输出引用该名 → **回显即可通过** |
| **E** | **要求下游改变"合同要求它不该改变"的字段** | 第 3 轮：A/B 均无触发源，合同要求合规下游**都输出空缺口**，判据却比较两点是否不同 → **惩罚合规、奖励违约** |
| **F** | **恒真判据**（不存在"错误的下游"会使其 FAIL） | 第 1 轮：纯否定式判据，**任何恒返回空数组的下游都自动通过** |
| **G** | **未声明"能证明什么 / 不能证明什么"的判据** | 三轮反复出现：判据被赋予超出其能力的含义 |
| **H** | **未附反例测试的"无法被绕过"类论断** | 第 2、3 轮：两次强断言（"对比式无法被空转满足""只能归因于某字段"）**均在下一轮被反例推翻** |
| **I** | **修改被测对象后不重估判据** | 第 3 轮的根因：R1 交付改变了合规下游的行为，而判据仍按其旧行为设计 |

### 每条新判据必须回答（**强制格式**）

1. **判定键**：取自哪个合同的哪一行（须通过 key audit）
2. **条件**：由哪些真实合同字段构造
3. **判据**：机器可判定的表达式
4. **恒失败场景**：**描述一种行为错误的下游，使本条 FAIL**
   （写不出 → 本条为恒真，**禁止发布**）
5. **能证明什么 / 不能证明什么**（明确到"传递级 / 理解级"）
6. **对合规下游的行为假设**：该假设是否已被合同或实测支持
7. **若被测对象（合同）变更，本条的哪一部分会失效**
