## 1. 裁定 #1 的执行结果：KERT 侧已修正

### 1.1 我发现的真实缺陷

实测所有 `bank-front-*` 技能返回**同一份通用内容**（R1 拜访报告），
**与所请求的技能无关**。

**根因**：`run_pkg` 恒以 `kind="generic"` 调用模型适配器，
且**执行后不校验输出是否符合该包自身的 output-schema**。
→ 调用方请求"事实对账"，得到的却是"拜访报告"，**且 `status=ok`**。

### 1.2 修复内容（KERT 仓，提交 `0b7c83f`）

| # | 修复 |
|---|---|
| 1 | `_load_packages` 新增抽取 `schema_keys`（该包 output-schema 的顶层键） |
| 2 | `run_pkg` 传入**技能专属 kind** `pkg:<skill_id>` |
| 3 | `run_pkg` **执行后按 `schema_keys` 校验输出，缺失即 fail-closed 拒绝返回** |
| 4 | `DeterministicLlmAdapter.complete` 透传 `system`，新增 `pkg:` 分支**按该技能 schema 生成结构** |

### 1.3 诚实性标注（**重要**）

确定性输出**显式标注为占位**：

```
schemaVersion: "deterministic/1.0"
status:        "DETERMINISTIC_PLACEHOLDER"
warnings:      ["确定性适配器输出：结构符合本技能 output-schema，
                 但内容为占位，不构成分析结论，不得据此作业务判断。"]
```

且空集合附注：「空表示适配器未生成条目，**不代表无此事项**」。

**理由**：若无此标注，结构合法但无内容的响应会被误认为分析结果。

### 3.2 「14 项复算」的**精确表述**（修正 QA 指出的过度声称）

**QA 第二轮指出（属实）**：我先前称"14 项实测复算"，
但当时 `recompute()` 对**所有**指标一律求和 ——
而 RATIO/DAYS 型指标**求和无意义**（比率之和、天数之和都不表示任何东西）。
**这属过度声称，已修正。**

**现按 `recomputeKind` 分派，14 项的复算强度并不相同**：

| 复算方式 | 项数 | 含义 | 强度 |
|---|---|---|---|
| `SUM_FLOW` | 3 | 流量型，跨期求和有意义（营收/净利润/经营现金流） | **真复算** |
| `LATEST_STOCK` | 5 | 存量型，**只取期末值**；明确声明**不做跨期求和**（避免余额重复计入） | **真复算（不求和）** |
| `RATIO_DERIVED` | 1 | **由组分按公式逐期复算，并与夹具值交叉校验**（资产负债率 = 负债/资产） | **真复算 + 交叉校验** |
| `DAYS_DERIVED` | 1 | 同上（现金转换周期 = AR + INV − AP） | **真复算 + 交叉校验** |
| `DAYS_OBSERVED` | 3 | **公式所需输入不可得**（如赊销收入未提供）→ **只能取观测值** | **仅观测，非复算** |
| `AVG_FROM_DAILY` | 1 | 按去重后逐日平均复算（日均存款） | **真复算** |

**交叉校验实际结果**：

```
DEBT_ASSET_RATIO      按公式复算 23/23 期与夹具值一致（容差 0.5%）
CASH_CONVERSION_CYCLE 按公式复算 23/23 期与夹具值一致
```

**必须说清的两点**：

1. **3 项 `DAYS_OBSERVED` 不是"复算"**，而是取观测值。
   其定义中已明确标注：
   > 「公式所需输入不可得；只能取观测值，**不得声称按公式复算**。」

2. 因此**准确表述应为**：
   > 「14 项可经数据集校验，其中 **11 项为真复算**（含 2 项按公式逐期交叉校验）、
   > **3 项为观测值取值**（公式输入不可得，已如实标注）。」

**教训**：与本轮根本错误同源 —— **用"求和"这个统一动作冒充"按各自公式复算"**，
形式上都是"跑了复算"，实质上一个比率和一个金额被同等对待。
