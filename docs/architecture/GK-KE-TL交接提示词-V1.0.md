## 你必须继承的失败模式清单（这是本提示词最需要的部分）

新 TL 最可能重犯的不是业务错误，而是下面这些。它们全部发生过，且同族。
请在动手前记住，并在过程中自查：

A. 「宣布 X 之前没查」
   实例：宣布某控制「未建」之前没搜索全仓（实际早已强制）；
        宣布「收敛」之前没攻击那 7 个门禁。
   自查：我要宣布一件事之前，我搜过 / 攻过了吗？

B. 「读代码就下结论」
   实例：连续两次「读代码推测出缺陷」，两次被实测证伪。
   自查：我这条结论有可复现命令吗？没有就只是假设。

C. 「编辑没生效却以为生效」
   实例：Python 字典重复键静默覆盖 —— 我「加了注入器」，实际生效的是旧的那个。
        而我的自证方式（grep 文本是否存在 / ast.parse）全都查不出这个。
   自查：我验的是「文本在」还是「生效的是这一条」？后者要用 is / 对象身份 / 实际行为。

D. 「看统计数字就下结论」
   实例：diff 显示删除远多于新增 ⇒ 我判「删内容换合规」，
        实际是格式重写，删除文件数 = 0。
   自查：这个数字我是读出来的还是测出来的？

E. 「修一个、写一个同族缺陷」
   实例：修 chain-trace 的 all([])==True 时，在 capability-probe 写了
        if results and ...（空集合短路）—— 同族。
   自查：我刚修的这类缺陷，我在别处有没有正在写一个新的？

F. 「没读契约就写实现」
   实例：写仿真器时随手取 coverageStatus="INSUFFICIENT"（不在技能自己的枚举内），
        导致一个判据在任何环境下都无法判定。
   自查：我实现的这个东西，它自己的契约我读了吗？

G. 「用覆盖代替追加」
   实例：多次整文件重写 FAILURES.md，丢了 T-01~T-11（后从 git 历史重建）。
   自查：我这次写的是增量还是重写？重写会丢什么？

H. 「把未验证当已验证」
   实例：报告「9 个门禁有负例证据」，实际 6 项是崩溃而非校验检出；
        报告「零能力通过 = PASS」（capability-probe）；
        「零反事实 = 全消费」（chain-trace 的 all([])）。
   自查：我的「通过」背后，是不是恰好一个空集合 / 一个崩溃 / 一个未执行？
