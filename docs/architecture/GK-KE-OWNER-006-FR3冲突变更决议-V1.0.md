## 1. 冲突是什么（**先陈述事实，再给裁定**）

### 1.1 既有规则原文

`specs/knowledge-architecture/capabilities/SIM-CAP-FACT-RECON.json`：

```json
{"id":"SIM-RULE-FR-3","name":"多指标必需","rule":"对账须覆盖三层 14 项；缺层即失败"}
```

### 1.2 与之冲突的建议书要求

建议书 §6.1 原文：

> 「**指标目录可以宽，单次任务应当窄，首页显示应更窄。**
> 指标目录回答系统理解哪些量；任务选集回答本次需要哪些量；首页回答哪些量最有助于现场沟通。
> **不能用首页只能放 8 项，推导底层只能定义 8 项。**」

建议书 §6.3 / §5.3 原文（关于用电量）：

> 「用电量仅作为**有适用性证明**的生产代理变量。它**不能成为服务业、贸易类企业的必填经营活力指标**。」

### 1.3 冲突的实质（**三点**）

| # | 冲突点 | 说明 |
|---|---|---|
| **C-a** | **"14 项"被固定为下限** | 建议书要求按任务选集，不同任务不同指标；固定 14 项等于取消选集 |
| **C-b** | **"缺层即失败"过于刚性** | 数据不可得时应输出 `UNKNOWN` 并说明覆盖，而非直接失败 |
| **C-c** | **可能强制不适用指标** | 若某指标（如用电量）对某行业不适用，"必填"即产生错误要求 |

**→ 冲突真实存在，非措辞问题。**

### 1.4 为什么不就地改（**关键纪律**）

建议书 §14.1 原文：

> 「若要改变条件范围，必须通过**显式差异记录**，**而非改写历史结论**。」

`SIM-RULE-FR-3` 是**既有受控合同内容**。直接编辑会：
- 抹去"曾经如此规定"的事实
- 使已有证据/测试的引用基础失效
- 违反 AGENTS.md「合同源变更先于生成物与实现」的变更纪律

## 2. Owner 裁定

### 2.1 裁定结果

| 项 | 裁定 |
|---|---|
| 冲突 | **确认存在** |
| 处置方式 | **受控变更**：`SIM-RULE-FR-3` **保留原文**并标记为 **SUPERSEDED**，另立 `SIM-RULE-FR-3-R1` 承载新语义 |
| 生效范围 | 仅首期 SIM 访前链；不影响其他循环 |

### 2.2 新规则 `SIM-RULE-FR-3-R1` 的语义

```
对账须覆盖由 TaskTemplate 选定的必需指标子集。
  - 必需子集由任务选出，非固定 14 项（依据 §6.1 目录/选集分离）
  - 缺层时的行为按数据条件分级：
      可选指标缺失 → 输出 UNKNOWN + 覆盖说明，不失败
      必需指标缺失 → 报告 COVERAGE_INSUFFICIENT，不静默通过
      指标对该行业不适用 → 输出 NOT_APPLICABLE（依据 §5.3）
  - 不得因"缺层"直接判失败而不区分原因（依据 §6.5 五维可得性）
```

### 2.3 与 WP03 交付物的关系

WP03 已设计：
- **15 项首批指标**（按 R01/R03/R06/R08/R12/R14 反推）
- **8 项可比性前置门禁**
- **五维可得性**（`availability/authorization/coverage/freshness/retrievalOutcome`）

**→ `SIM-RULE-FR-3-R1` 与 WP03 设计一致**，A2（WP03 落地）可直接采用。
