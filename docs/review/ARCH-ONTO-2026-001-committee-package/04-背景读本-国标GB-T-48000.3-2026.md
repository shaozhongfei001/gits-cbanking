| 项 | 值 |
|---|---|
| 标准号 | GB/T 48000.3-2026 |
| 中文名称 | 标准数字化 第3部分：本体建模要求 |
| 英文名称 | Standard digitalization—Part 3: Requirement for ontology modeling |

## 2. 关键认知：该标准建模的对象是「标准文件」，不是「银行业务」

GB/T 48000.3-2026 的核心实体是 `Standard`（标准）、标准要素、层次结构、信息单元、制定程序等——它服务于"把国家标准/行业标准本身数字化"的场景。本项目的建模对象是银行运营概念（客户、产品、主张、证据……），**领域不同**。

## 3. 本方案的适用方式：参照适用（明示裁剪，非规避）

| | 内容 |
|---|---|
| **继承**（通用要求） | ① 本体建模通用要求；② 形式化要求（W3C 技术栈）；③ 实体类型/属性/关系的定义规则；④ 本体公理与规则；⑤ 扩展方式（只增不改、破坏性变更升版本）；⑥ 元数据描述项 |
| **不继承**（专有实体） | 标准文件、标准要素、层次结构、信息单元、制定程序等标准数字化专有概念 |
| **加严** | 「校验空转 = 失败」「引用必须钉版本」等规则严于一般惯例 |
| **落地形式** | 转化为 9 条可执行规则 R1~R9 + 自动符合性检查（`make conformance`），每条规则有具名失败码，逐条可验 |

**为什么不构成规避**：参照适用（apply by reference）是推荐性国标在企业域的常规适用方式；方案对通用要求全量继承并加严，仅对与本领域无关的专有实体做**明示、留痕**的裁剪，裁剪清单将写入模块内的《国标符合性声明》逐条可查。

**诚信声明**：截至送审日，R1~R9 与标准条款的映射基于官方平台元数据与公开摘要整理；**正式文本获取后将逐条复核并更新符合性声明**（已列为落地计划 Wave 0 的前置工作项）。
