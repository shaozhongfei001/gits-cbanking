# 六列权威与发布依赖表（M-01 关闭证据）

## 1. 模型定义（委员会 §3.2 口径）

仅当 ① 术语定义 Owner ② 身份与 ID Owner ③ 实例事实 Owner ④ 发布制品 Owner ⑤ 消费依赖方向 ⑥ 变更审批与兼容性责任 六列出现**闭环依赖**（A 发布以 B 权威决定为前提 ∧ B 发布以 A 权威决定为前提，且无单向版本契约可打断），才构成权威循环。

## 3. 发布依赖图（单向性验证）

```
银行源系统/数据平台 ──(实例事实)──▶ L1 公共语义核心（定义）
                                        │ ④发布（独立流水线）
              ┌───────────────────────────┼───────────────────────────┐
              ▼ 钉值消费（单向）           ▼ 钉值消费（单向）           ▼ 引用（单向）
        L3 GITS 运行本体            L2 KERT 元模型              L4 集成契约注册表
              │ ⑤钉 L1/L2/L4 版本        │ describesProduct→L1        │ 绑定 L2/L4 版本
              ▼                          ▼                          ▼
        GITS 运行时                  KERT 运行时                  双侧运行时校验
```

- 所有消费依赖均为**单向钉值**（消费者钉发布方的不可变版本制品），不存在「A 发布须 B 权威决定 ∧ B 发布须 A 权威决定」的反向边；
- L1 的发布不依赖 L2/L3/L4 任何权威决定；L2 对 L1 仅为引用（describesProduct），不构成发布前提；
- **结论：六列无闭环依赖 ⇒ 无权威循环**（V1.2 论断撤回）。原 E1 重新定性为「归属含混 + 发布耦合」，已由四层模型 + 逐术语权威矩阵（03 号）消除。

## 4. 冲突裁决顺序（防未来循环）

变更审批冲突时裁决顺序：① 实例事实以源系统/数据平台为准；② 术语定义以各层 T-Box Owner 为准；③ 跨层引用冲突由 Integration Contract Owner 召集三方评审；④ 兼容性等级冲突按 07 号矩阵 major 处理。任何一环不得绕过上游直接改下游定义。
