# 验证状态模型与状态跃迁表（关闭条件 7）

## 1. 五态定义

| 状态 | 定义 | 谁可记录 | 记录物 |
|---|---|---|---|
| `PASS` | 验证场景执行且全部断言通过（**实际目标数 > 0**，正/负/变异夹具命中数达标） | 独立 QA | 执行日志 + 目标数 + 夹具命中数 + 制品哈希 |
| `FAIL` | 验证场景执行且存在断言失败 | 任何人/CI | 失败详情（先记 FAILURES 再修复） |
| `NOT_EVALUATED` | 无生产实例且无受控夹具，无法执行验证 | 独立 QA | 原因 + 关联依赖（如 D2） |
| `DESIGN_ONLY` | 仅设计存在，无实现可验 | 设计 Owner | 设计引用 |
| `WAIVED_FOR_DEVELOPMENT` | 经批准的临时豁免，**仅允许继续开发** | Owner（含到期日与解除条件） | 豁免登记（原因/责任人/解除条件/到期日） |

## 2. 状态跃迁表

| 从 → 到 | 允许条件 | 审批 |
|---|---|---|
| 任意 → `FAIL` | 任一断言失败（随时发生） | 无需（事实记录） |
| `DESIGN_ONLY` → `NOT_EVALUATED` | 实现已存在但无实例/夹具 | QA 确认 |
| `NOT_EVALUATED` → `PASS`/`FAIL` | 获得经 Owner 批准的实例或受控夹具后执行 | QA 执行 |
| `FAIL` → `PASS` | 修复后重跑全量场景（含变异复验） | QA 执行 |
| 任意（非 PASS） → `WAIVED_FOR_DEVELOPMENT` | Owner 批准豁免（必须登记解除条件与到期日） | **Owner** |
| `WAIVED_FOR_DEVELOPMENT` → `PASS` | 解除条件满足 + 复验通过 | QA 执行 + Owner 确认关闭 |
| `WAIVED_FOR_DEVELOPMENT` → `FAIL` | 到期未解除或复验失败 | 自动（到期检查脚本） |
| **任何状态 → `PASS`** | **禁止**未经执行直接改写（尤其 WAIVED→PASS 必须经复验） | — |

## 3. 门禁映射（核心纪律）

| 门禁类型 | 允许通过的状态 |
|---|---|
| 开发继续（commit/merge 到开发分支） | `PASS`、`WAIVED_FOR_DEVELOPMENT`（带到期检查）、`DESIGN_ONLY`（非关键场景） |
| 实施完成门禁（`IMPLEMENTED`） | 关键场景全部 `PASS` 或 `NOT_EVALUATED`（附依赖登记）；**零 `FAIL`**；`WAIVED` 须全量登记且到期日均在未来 |
| 激活门禁（`OWNER_ACTIVATED`） | 关键场景全部 `PASS`（**实际目标数 > 0**）；**`WAIVED_FOR_DEVELOPMENT` 与 `NOT_EVALUATED` 一律不得满足激活退出标准**；关键关系（如产品关系 3 属性）必须有经 Owner 批准的实例或受控测试夹具 |

## 4. 在 Product 零实例问题上的应用（M-03）

- `requiresProduct`/`complementsProduct`/`mutuallyExclusiveWith` 三场景当前 = `NOT_EVALUATED`（依赖 D2：40 悬空引用分类）；
- D2 未决期间：禁止标 `PASS`、禁止以 `WAIVED_FOR_DEVELOPMENT` 充当激活依据、激活门禁中这三个场景为硬阻塞；
- D2 解除后：按分类结果补实例/夹具 → 目标数 > 0 的执行 → `PASS`/`FAIL`。
