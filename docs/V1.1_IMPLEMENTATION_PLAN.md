## 二、Phase 1: 数据层+ScenarioDataProvider

### 目标
建立SCENARIO_DATA_ROOT配置和V1.1数据读取适配

### 任务清单

#### 1.1 创建ScenarioDataProvider接口
- **位置**: `modules/operational-ontology/src/main/java/com/gien/gits/ontology/port/ScenarioDataProvider.java`
- **方法**:
  ```java
  public interface ScenarioDataProvider {
      InputStream readFile(String relativePath);
      List<String> listFiles(String directory);
      String getRootPath();
      String getVersion();
  }
  ```

#### 1.2 实现FileSystemScenarioDataProvider
- **位置**: `apps/api/src/main/java/com/gien/gits/api/adapter/FileSystemScenarioDataProvider.java`
- **逻辑**: 读取SCENARIO_DATA_ROOT下的文件
- **配置**: `gits.scenario.data-root` 属性

#### 1.3 创建symlink机制
- **位置**: `scenario_data/current` → 指向V1.1数据包
- **脚本**: `scripts/switch-scenario-version.sh`
- **默认值**: `scenario_data/` (当前workspace内的V1.1数据)

#### 1.4 重构ScenarioSeedDataService
- **修改**: 注入ScenarioDataProvider替换classpath读取
- **保留**: 旧classpath读取作为fallback

#### 1.5 配置application.yaml
- **新增**:
  ```yaml
  gits:
    scenario:
      data-root: "${SCENARIO_DATA_ROOT:#{systemProperties['user.dir']}/scenario_data}"
      version: "${SCENARIO_VERSION:v1.1}"
  ```

#### 1.6 V1.1数据读取适配器
- **新建**: `V1_1_DataLoader` 读取V1.1 JSON/CSV/MD文件
- **映射**: V1.1数据结构 → 现有领域对象
- **重点文件**:
  - `02_master_data/customers.json` → Customer
  - `02_master_data/legal_entities.json` → LegalEntity
  - `02_master_data/group_structures.json` → GroupStructure
  - `03_bank_data/accounts.json` → Account
  - `03_bank_data/facilities.json` → Facility
  - `03_bank_data/transactions.json` → TransactionRecord
  - `04_external_data/events.json` → ExternalEvent (新增)
  - `05_knowledge/product_rules.json` → ProductKnowledgeVersion (新增)
  - `05_knowledge/kyc_questions.json` → KycQuestion
  - `05_knowledge/ontology.json` → OntologyDefinition
  - `06_interactions/` → Interaction + Evidence

### 验收标准
- [ ] `SCENARIO_DATA_ROOT` 可配置切换V1.0/V1.1数据
- [ ] V1.1所有JSON文件可被正确解析
- [ ] 种子数据加载后H2数据库包含V1.1完整数据
- [ ] symlink切换机制工作正常

## 十一、技术约束

1. **不迁移V1.1数据文件** — 通过ScenarioDataProvider读取
2. **不硬编码绝对路径** — 通过SCENARIO_DATA_ROOT配置
3. **不破坏V1.0已有实现** — EXTEND而非REWRITE
4. **不创建16个独立Router页面** — 复用现有页面+Tab+Drawer
5. **不修改V1.1原始数据包** — 只读
6. **不执行无HG确认的副作用** — Draft→Review→Accept/Edit/Reject
7. **meeting_gold_transcript.txt仅作TEST GOLD** — 不作为生产输入
